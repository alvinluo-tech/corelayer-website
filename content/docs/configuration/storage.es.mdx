title: Almacenamiento
description: Donde CoreLayer guarda el estado y como cambiar entre SQLite, Supabase y PostgreSQL.

CoreLayer guarda el estado localmente por defecto y puede correr contra Supabase o un PostgreSQL propio. El modo de almacenamiento se elige al arrancar, no por peticion.

## Modos de almacenamiento

| Modo | Valor | Descripcion |
|------|-------|-------------|
| SQLite | `local` (por defecto) | Base de datos en archivo, sin configuracion |
| Supabase | `cloud` | PostgreSQL en la nube, tu propio proyecto |
| PostgreSQL | `postgres` | PostgreSQL autogestionado |

El modo vive en su propio archivo, `storage.json`, junto a `config.json` en la zona de configuracion:

```json
{
  "storageMode": "local",
  "dbConfig": {
    "supabaseUrl": "https://your-project.supabase.co",
    "supabaseServiceKey": "…",
    "postgresUrl": "postgresql://user:pass@host:5432/corelayer"
  }
}
```

`dbConfig` solo se requiere para los modos cloud y postgres. La variable de entorno `DATABASE_URL` tambien se respeta para PostgreSQL.

El cambio se hace en **Ajustes → Almacenamiento**, que escribe este archivo. El nuevo modo se aplica tras reiniciar el daemon; no es un hot-swap en vivo.

## Diseno en disco

El estado local se divide en seis zonas bajo el directorio home de CoreLayer (`JARVIS_HOME` lo mueve; el valor por defecto en escritorio es `~/.jarvis`):

```text
~/.jarvis/
├── config/      config.json · routing.json          (sin secretos)
├── security/    credentials.json                     (0600 en POSIX)
├── memory/      USER.md · MEMORY.md · journal/ · dreams/
├── storage/     jarvis.db
├── worktrees/   active/ · snapshots/
└── cache/       symbol-graph/ · mcp-schemas/ · delegation-pipes/
```

Las credenciales se leen de `security/credentials.json`; un `config/credentials.json` heredado se sigue respetando si la nueva ubicacion no existe.

En modo sidecar el shell puede sobrescribir la raiz con `JARVIS_APP_DATA_DIR`, `JARVIS_LOG_DIR` y `SQLITE_DB_PATH`.

### Excepciones conocidas

Dos archivos aun se resuelven en ubicaciones heredadas en lugar del layout de seis zonas:

- `mcp-servers.json` se lee de `~/.jarvis/config/mcp-servers.json`
- la ruta de SQLite sigue la resolucion de app-paths (`data/jarvis.db` salvo que se defina `SQLITE_DB_PATH`)

Ambos se documentan como excepciones en lugar de describirse silenciosamente como parte del nuevo layout.

## Elegir un backend

- **SQLite** — una maquina, offline, consultas mas rapidas. Por defecto.
- **Supabase** — varios dispositivos y backups gestionados; el proyecto y sus politicas son tuyos.
- **PostgreSQL** — ya operas una base de datos y no quieres otro plano de control.

No hay replicacion en segundo plano entre backends: cambiar de modo significa que el daemon lee y escribe el backend elegido.
