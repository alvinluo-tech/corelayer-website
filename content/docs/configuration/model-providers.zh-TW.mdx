title: 模型供應商
description: 設定模型閘道可路由的供應商。

所有模型呼叫都經由同一個 OpenAI 相容轉接器。因此一個供應商就是 `baseURL` 加一把密鑰，而不是一套廠商 SDK；新增一個支援 OpenAI 線格式的供應商屬於設定，而不是寫程式碼。

## 支援的供應商 ID

以下 ID 由供應商解析器識別，包含各自的環境變數與預設 base URL：

| 供應商 | ID | 預設 base URL |
|--------|----|---------------|
| DeepSeek | `deepseek` | `https://api.deepseek.com/v1` |
| OpenAI | `openai` | `https://api.openai.com/v1` |
| Anthropic | `anthropic` | `https://api.anthropic.com/v1` |
| Google Gemini | `gemini` | `https://generativelanguage.googleapis.com/v1beta/openai` |
| Groq | `groq` | `https://api.groq.com/openai/v1` |
| OpenRouter | `openrouter` | `https://openrouter.ai/api/v1` |
| MiMo（小米） | `mimo` | `https://token-plan-ams.xiaomimimo.com/v1` |
| Qwen（阿里） | `qwen` | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| Ollama | `ollama` | `http://localhost:11434/v1` |

Gemini 的 ID 是 `gemini`，不是 `google`——後者只出現在環境變數名 `GOOGLE_API_KEY` 中。

## 設定放在哪裡

| 檔案 | 內容 |
|------|------|
| `~/.jarvis/config/config.json` | `providers[]`、`activeProvider`、`activeModel`、路由規則、預設值 |
| `~/.jarvis/security/credentials.json` | API Key，按供應商 id 索引 |

API Key 永遠不會寫進 `config.json`。

```json
{
  "version": 1,
  "activeProvider": "mimo",
  "activeModel": "mimo-v2.5-pro",
  "providers": [
    {
      "id": "deepseek",
      "name": "DeepSeek",
      "type": "openai_compatible",
      "baseURL": "https://api.deepseek.com/v1",
      "enabled": true
    }
  ]
}
```

`type` 對遠端供應商都是 `openai_compatible`，本機服務為 `ollama`。

## 密鑰與 base URL 的解析順序

對一個供應商，解析器依次檢查：

1. `security/credentials.json` 與 `config.json` 中的供應商條目
2. 供應商對應的環境變數（例如 `DEEPSEEK_API_KEY`、`ANTHROPIC_AUTH_TOKEN`）
3. 內建預設 base URL

如果 URL 不能被識別為供應商名，解析器會嘗試從主機名推斷（例如 `api.deepseek.com` → `deepseek`）。

完整環境變數表見 [設定檔](/docs/reference/config-file#environment-variables)。

## 路由與降級

- `activeProvider` / `activeModel` 定義預設目標。
- `routingRules[]` 把 `taskType` 映射到 `modelId`，支援可選 `conditions`。
- 當某供應商連續失敗，它會被標記為「死亡」並進入冷卻（連續兩次失敗，之後指數退避），後續呼叫會跳過它，而不是再付出同樣的逾時。一次成功即重置。

## 模型族差異

轉接器按模型族做少量調整，而不把它們暴露成設定項：

- 推理模型（`o1`…`o4` 及預覽版）使用這些端點接受的參數，而非聊天預設值。
- Anthropic 模型經 OpenAI 相容端點呼叫，因此工具呼叫與串流行為與其他供應商一致。

## 關於「目前模型」

本頁刻意不列出模型名稱。模型 ID 的變更速度快於文件：請使用 **設定 → 模型**（在供應商提供模型清單時會讀取它），或參考供應商官方文件。在這裡寫死模型名，一個版本內就會過時。
