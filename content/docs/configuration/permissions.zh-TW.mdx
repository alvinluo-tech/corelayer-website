---
title: 權限
description: 設定權限守護的風險策略與按應用覆寫。
---

權限守護對每次工具呼叫決定：直接執行、執行並提示、掛起詢問，還是拒絕。這個決定是工具宣告風險與策略的純函式。

## 風險 → 動作

| 風險 | 預設動作 |
|------|----------|
| `low` | `auto` — 靜默執行 |
| `medium` | `notify` — 執行並提示 |
| `high` | `confirm` — 掛起直到你決定 |
| `critical` | `deny` — 拒絕 |

## 預設策略

```ts
defaultPolicy: {
  low: "auto",
  medium: "notify",
  high: "confirm",
  critical: "deny",
}
```

這是守護行程實際執行的策略，映射定義在 `@jarvis/permission-guard` 中並作用於每次工具呼叫。

**它目前還不支援使用者設定。** 守護以預設值構造，`config.json` 中也沒有權限段落——本檔案歷史版本描述過一個 `permissions.rules` 陣列，那個陣列並不存在，寫進去也不會生效。

## 按應用覆寫

守護的設定結構支援按應用覆寫：

```ts
appPermissions: {
  "filesystem": { write: true,  execute: false },
  "untrusted-mcp": { write: false, execute: false },
}
```

各旗標的映射：

| 風險 | `write: true` | `write: false` |
|------|---------------|----------------|
| `medium` | `notify` | `confirm` |
| `high` | `confirm` | `deny` |

| 風險 | `execute: true` | `execute: false` |
|------|-----------------|------------------|
| `critical` | `confirm` | `deny` |

`low` 始終是 `auto`。

覆寫在存在時會被評估，但守護行程中目前沒有程式碼從磁碟讀取它們，因此只對以覆寫設定構造守護的呼叫方生效。

## 語音模式

語音執行不論風險都更嚴格：唯讀動作自動放行，其餘都需要確認。口頭發起比手動輸入更容易被誤觸發。

## 核准請求

動作為 `confirm` 時，守護不會把決定留在記憶體裡：

1. 持久化 `approval_request`，包含動作摘要、風險、範圍與過期時間
2. 掛起執行
3. 介面展示請求——核准、拒絕或記住
4. 決定後恢復或終止執行

端點：

```text
GET  /api/approvals
GET  /api/approvals/:id
POST /api/approvals/:id/approve
POST /api/approvals/:id/deny
POST /api/approvals/:id/remember
POST /api/approvals/batch/approve
POST /api/approvals/batch/deny
POST /api/approvals/expire-stale
```

「請求已過期」是真實狀態：無人值守佇列會堆積沒人應答的請求，`expire-stale` 會把它們關閉，而不是讓執行永久掛起。

## 權限記憶

「記住」會把決定記錄在動作摘要上——是具體動作，而不是工具名。同一動作不再詢問；不同路徑、指令或參數集合會產生不同摘要，仍會詢問。

## 稽核

每次決定都寫入 `audit_log`，可按條件查詢：

```text
GET /api/audit?actor=jarvis&action=tool.execute&riskLevel=high&since=2026-10-01T00:00:00Z&limit=50
```

一筆記錄包含 `actor`、`action`、`resource`、`riskLevel`、`permissionDecision`、`confirmedByUser`、`result`、`metadata` 與 `createdAt`。
