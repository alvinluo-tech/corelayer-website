---
title: Proveedores de Modelos
description: Configura los proveedores a los que el Model Gateway puede enrutar.
---

Cada llamada de modelo pasa por un unico adaptador compatible con OpenAI. Por eso un proveedor es una `baseURL` mas una clave, no un SDK por vendedor; agregar un proveedor que habla el formato OpenAI es configuracion, no codigo.

## IDs de proveedor soportados

Estos IDs los reconoce el resolver de proveedores, con sus variables de entorno y base URL por defecto:

| Proveedor | ID | Base URL por defecto |
|-----------|----|----------------------|
| DeepSeek | `deepseek` | `https://api.deepseek.com/v1` |
| OpenAI | `openai` | `https://api.openai.com/v1` |
| Anthropic | `anthropic` | `https://api.anthropic.com/v1` |
| Google Gemini | `gemini` | `https://generativelanguage.googleapis.com/v1beta/openai` |
| Groq | `groq` | `https://api.groq.com/openai/v1` |
| OpenRouter | `openrouter` | `https://openrouter.ai/api/v1` |
| MiMo (Xiaomi) | `mimo` | `https://token-plan-ams.xiaomimimo.com/v1` |
| Qwen (Alibaba) | `qwen` | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| Ollama | `ollama` | `http://localhost:11434/v1` |

El ID de Gemini es `gemini`, no `google`; el segundo solo aparece en el nombre de la variable `GOOGLE_API_KEY`.

## Donde vive la configuracion

| Archivo | Contenido |
|---------|-----------|
| `~/.jarvis/config/config.json` | `providers[]`, `activeProvider`, `activeModel`, reglas de enrutado, valores por defecto |
| `~/.jarvis/security/credentials.json` | claves API, por id de proveedor |

Ninguna clave API se escribe en `config.json`.

```json
{
  "version": 1,
  "activeProvider": "mimo",
  "activeModel": "mimo-v2.5-pro",
  "providers": [
    {
      "id": "deepseek",
      "name": "DeepSeek",
      "type": "openai_compatible",
      "baseURL": "https://api.deepseek.com/v1",
      "enabled": true
    }
  ]
}
```

`type` es `openai_compatible` para todos los proveedores remotos y `ollama` para un servidor local.

## Resolucion de clave y base URL

Para un proveedor, el resolver comprueba en orden:

1. `security/credentials.json` y la entrada del proveedor en `config.json`
2. Las variables de entorno del proveedor (por ejemplo `DEEPSEEK_API_KEY`, `ANTHROPIC_AUTH_TOKEN`)
3. La base URL por defecto integrada

Si una URL no se reconoce como nombre de proveedor, el resolver intenta inferirlo del hostname (por ejemplo `api.deepseek.com` → `deepseek`).

La tabla completa de variables esta en [Archivo de Configuracion](/docs/reference/config-file#environment-variables).

## Enrutado y fallback

- `activeProvider` / `activeModel` definen el destino por defecto.
- `routingRules[]` mapean un `taskType` a un `modelId`, con `conditions` opcionales.
- Cuando un proveedor falla repetidamente se marca como muerto con cooldown (dos fallos consecutivos y luego backoff exponencial), asi las llamadas siguientes lo saltan en lugar de pagar el mismo timeout. Un exito lo resetea.

## Familias de modelos

El adaptador aplica pequenas adaptaciones por familia en lugar de exponerlas como configuracion:

- Los modelos de razonamiento (`o1`…`o4`, previews) reciben los parametros que esos endpoints aceptan, no los del chat por defecto.
- Los modelos Anthropic se llaman por el endpoint compatible con OpenAI, asi el tool calling y el streaming se comportan como en los demas.

## Que modelos son actuales

Esta pagina no lista nombres de modelos a proposito. Los IDs cambian mas rapido que la documentacion: usa **Ajustes → Modelos**, que lee la lista del proveedor cuando este la expone, o la documentacion oficial del proveedor. Fijar un nombre aqui queda obsoleto en una release.
