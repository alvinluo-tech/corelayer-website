title: 模型提供商
description: 配置模型网关可路由的供应商。

所有模型调用都经由同一个 OpenAI 兼容适配器。因此一个供应商就是 `baseURL` 加一个密钥，而不是一套厂商 SDK；新增一个支持 OpenAI 线格式的供应商属于配置，而不是写代码。

## 支持的供应商 ID

以下 ID 由供应商解析器识别，包含各自的环境变量与默认 base URL：

| 供应商 | ID | 默认 base URL |
|--------|----|---------------|
| DeepSeek | `deepseek` | `https://api.deepseek.com/v1` |
| OpenAI | `openai` | `https://api.openai.com/v1` |
| Anthropic | `anthropic` | `https://api.anthropic.com/v1` |
| Google Gemini | `gemini` | `https://generativelanguage.googleapis.com/v1beta/openai` |
| Groq | `groq` | `https://api.groq.com/openai/v1` |
| OpenRouter | `openrouter` | `https://openrouter.ai/api/v1` |
| MiMo（小米） | `mimo` | `https://token-plan-ams.xiaomimimo.com/v1` |
| Qwen（阿里） | `qwen` | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| Ollama | `ollama` | `http://localhost:11434/v1` |

Gemini 的 ID 是 `gemini`，不是 `google`——后者只出现在环境变量名 `GOOGLE_API_KEY` 中。

## 配置放在哪里

| 文件 | 内容 |
|------|------|
| `~/.jarvis/config/config.json` | `providers[]`、`activeProvider`、`activeModel`、路由规则、默认值 |
| `~/.jarvis/security/credentials.json` | API Key，按供应商 id 索引 |

API Key 永远不会写进 `config.json`。

```json
{
  "version": 1,
  "activeProvider": "mimo",
  "activeModel": "mimo-v2.5-pro",
  "providers": [
    {
      "id": "deepseek",
      "name": "DeepSeek",
      "type": "openai_compatible",
      "baseURL": "https://api.deepseek.com/v1",
      "enabled": true
    }
  ]
}
```

`type` 对远程供应商都是 `openai_compatible`，本地服务为 `ollama`。

## 密钥与 base URL 的解析顺序

对一个供应商，解析器依次检查：

1. `security/credentials.json` 与 `config.json` 中的供应商条目
2. 供应商对应的环境变量（例如 `DEEPSEEK_API_KEY`、`ANTHROPIC_AUTH_TOKEN`）
3. 内建默认 base URL

如果 URL 不能被识别为供应商名，解析器会尝试从主机名推断（例如 `api.deepseek.com` → `deepseek`）。

完整环境变量表见 [配置文件](/docs/reference/config-file#environment-variables)。

## 路由与降级

- `activeProvider` / `activeModel` 定义默认目标。
- `routingRules[]` 把 `taskType` 映射到 `modelId`，支持可选 `conditions`。
- 当某供应商连续失败，它会被标记为“死亡”并进入冷却（连续两次失败，之后指数退避），后续调用会跳过它，而不是再付出同样的超时。一次成功即重置。

## 模型族差异

适配器按模型族做少量适配，而不把它们暴露成配置项：

- 推理模型（`o1`…`o4` 及预览版）使用这些端点接受的参数，而非聊天默认值。
- Anthropic 模型经 OpenAI 兼容端点调用，因此工具调用与流式行为与其他供应商一致。

## 关于“当前模型”

本页刻意不列出模型名称。模型 ID 的变更速度快于文档：请使用 **设置 → 模型**（在供应商提供模型列表时会读取它），或参考供应商官方文档。在这里写死模型名，一个版本内就会过时。
