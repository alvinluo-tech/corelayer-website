title: 存储
description: CoreLayer 把状态存在哪里，以及如何在 SQLite、Supabase 与 PostgreSQL 之间切换。

CoreLayer 默认把状态存在本地，也可以改为运行在 Supabase 或自托管 PostgreSQL 上。存储模式在启动时确定，不按请求切换。

## 存储模式

| 模式 | 取值 | 说明 |
|------|------|------|
| SQLite | `local`（默认） | 零配置的本地文件数据库 |
| Supabase | `cloud` | 你自己的云 PostgreSQL 项目 |
| PostgreSQL | `postgres` | 自托管 PostgreSQL |

模式存放在独立文件 `storage.json` 中（与 `config.json` 同在配置分区）：

```json
{
  "storageMode": "local",
  "dbConfig": {
    "supabaseUrl": "https://your-project.supabase.co",
    "supabaseServiceKey": "…",
    "postgresUrl": "postgresql://user:pass@host:5432/corelayer"
  }
}
```

`dbConfig` 仅在 cloud 与 postgres 模式下需要。PostgreSQL 也支持环境变量 `DATABASE_URL`。

切换在 **设置 → 存储** 中完成，它会写入该文件。新模式由守护进程**重启后**生效，并非在线热切换。

## 磁盘布局

本地状态分布在 CoreLayer 主目录（可用 `JARVIS_HOME` 覆盖；桌面默认 `~/.jarvis`）下的六个分区：

```text
~/.jarvis/
├── config/      config.json · routing.json          （无密钥）
├── security/    credentials.json                     （POSIX 下 0600）
├── memory/      USER.md · MEMORY.md · journal/ · dreams/
├── storage/     jarvis.db
├── worktrees/   active/ · snapshots/
└── cache/       symbol-graph/ · mcp-schemas/ · delegation-pipes/
```

凭据从 `security/credentials.json` 读取；当新位置不存在时，仍兼容旧的 `config/credentials.json`。

在 sidecar 模式下，外壳可通过 `JARVIS_APP_DATA_DIR`、`JARVIS_LOG_DIR` 与 `SQLITE_DB_PATH` 覆盖根目录。

### 已知例外

有两个文件仍然解析到旧位置，而非六分区布局：

- `mcp-servers.json` 从 `~/.jarvis/config/mcp-servers.json` 读取
- SQLite 路径沿用 app-paths 的解析结果（除非设置 `SQLITE_DB_PATH`，否则为 `data/jarvis.db`）

这里把两者作为例外写明，而不是悄悄描述成新布局的一部分。

## 数据结构

数据库由 Drizzle 迁移管理。

| 分组 | 表 |
|------|----|
| 工作结构 | `workspaces`、`workspace_agents`、`projects`、`agent_profiles`、`tasks`、`artifacts`、`goals`、`plans` |
| 执行 | `agent_runs`、`agent_run_events`、`executor_runs`、`execution_logs`、`environment_sessions`、`environment_events` |
| 治理 | `approval_requests`、`permission_memories`、`capability_grants`、`pending_actions`、`tool_call_logs`、`audit_log`、`event_log` |
| 对话 | `conversations`、`messages` |
| 知识 | `memories`、`articles`、`reviews` |
| 配置 | `app_connections`、`model_profiles`、`scheduled_tasks` |
| 渠道 | `channel_accounts`、`channel_conversations`、`channel_messages` |

## 如何选择

- **SQLite** — 单机、离线、查询最快。默认。
- **Supabase** — 多设备，并希望托管备份；项目与策略由你掌控。
- **PostgreSQL** — 你已运维数据库，不想引入第三方控制面。

后端之间没有后台复制：切换模式即意味着守护进程读写你选定的后端。
