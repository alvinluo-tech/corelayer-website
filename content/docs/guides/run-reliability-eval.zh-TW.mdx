---
title: 執行可靠性評測
description: 度量對編碼 Agent 的變更是否真的讓它變好。
---

一次成功執行說明不了任何問題。本指南執行評測框架，用多次嘗試的一致性來判斷提示詞、策略或轉接器的變更。

## 前置條件

- 健康的模型閘道。執行器經 ACP 執行，因此它使用的變數同樣適用：
  - `ANTHROPIC_MODEL` — 必須是 DeepSeek 模型
  - `ANTHROPIC_BASE_URL`
  - `ANTHROPIC_AUTH_TOKEN`
- 已安裝 `acpx`
- 在 `daemon/` 目錄下執行

## 基線執行

```powershell
cd daemon
$env:ANTHROPIC_MODEL='deepseek-v4.1-flash'
$env:ANTHROPIC_BASE_URL='http://127.0.0.1:8791'
$env:ANTHROPIC_AUTH_TOKEN='sk-...'

npx tsx src/eval/cli.ts --corpus src/eval/corpora/core.json --k 3
```

每次嘗試都會獲得一個全新的暫存 git 儲存庫，已播種任務檔案與一個空提交，因此任務之間不會互相污染，「什麼都不改」這類任務才有意義。

請讀 `pass^k` 而不是平均值：`pass^3` 表示在每一次嘗試中都成功的任務比例。

## 對行為變更做 A/B

```powershell
npx tsx src/eval/cli.ts --corpus src/eval/corpora/holdout.json --k 3 --compare JARVIS_REFLECTION=1
```

它把語料跑兩遍——變數未設定、再設定——並給出配對結論：

| 結論 | 解讀 |
|------|------|
| `improved` | 總體超過容差，且沒有任何任務退步 |
| `regressed` | 總體下降 |
| `mixed` | 均值上升但有任務失去可靠性——**不是**改進 |
| `unchanged` | 全部落在容差帶內 |

## 決策

只有以下四條全部滿足，才把變更提升為預設：

1. 結論為 `improved`
2. `lostReliability` 為空
3. `tokensPerSuccess` 上升不超過約 20%
4. 複跑一次仍滿足 1–3

否則保持預設關閉。

## 解讀失敗

| 症狀 | 可能原因 |
|------|----------|
| 連續大量 `timed-out` | 閘道抖動；ACP 會掛到預算耗盡而不是快速失敗 |
| `VOID` 嘗試 | 環境故障（配額、連線被拒、5xx）——按設計不計入比率 |
| 假陽性 | 執行器聲稱成功但檢查失敗；該任務的完成證據太弱 |
| 假陰性 | 檢查失敗而 Agent 自報失敗；檢查任務定義 |
| `--compare` 出現 `mixed` | 某個任務退步但均值上升——聚合門檻看不見的情況 |

## 新增任務

優先使用確定性腳本可判定的檢查。當內容比較困難（格式、順序、散文）時，播種一個 `check.js` 並用 `command` 檢查評分。檢查類型有 `file-exists`、`file-missing`、`file-contains`、`file-unchanged` 與 `command`；`file-unchanged` 比較摘要，這是檢驗「別動其他東西」的唯一方式。
