CoreLayer 中每一次工具执行决定都会被记录。本指南展示如何查询与解读审计条目。

## 访问审计日志

审计条目由 `GET /api/audit` 提供，并在控制中心展示。它与审批（`/api/approvals`）以及事件日志（`/api/events`）是彼此独立的资源。

## 日志条目格式

一条记录包含：

```text
createdAt          2026-10-21T14:32:01Z
actor              jarvis
action             tool.execute
resource           filesystem:write /workspace/README.md
riskLevel          high
permissionDecision confirm
confirmedByUser    true
result             success
metadata           { ... }
```

## 过滤日志

`GET /api/audit` 支持：

- `actor` — 谁执行了该动作
- `action` — 执行了什么
- `riskLevel` — `low` | `medium` | `high` | `critical`
- `since` — ISO 时间下界
- `limit` / `offset` — 分页

响应为 `{ entries, total, count }`。

## 常见用例

### 安全审查

查看哪些高风险动作被批准：

1. 查询 `GET /api/audit?riskLevel=high&since=2026-10-01T00:00:00Z`
2. 逐条查看 `resource` 与 `metadata`
3. 确认你期望人工决定的地方 `confirmedByUser` 为 `true`

### 调试

查找某个工具调用为何没有执行：

1. 按 `action` 过滤
2. 查看 `permissionDecision`——`deny` 表示被策略拦截
3. 用 `GET /api/runs/:id/events` 交叉核对 run id

### 合规

生成状态变更记录：

1. 先用 `riskLevel=high` 查询，再用 `riskLevel=critical` 查询
2. 导出返回的条目
3. 检查所有 `confirmedByUser: false` 的条目——它们是被自动决定的

## 日志保留

没有保留期设置。条目一直存放在所配置数据库的 `audit_log` 表中。本文件早期版本描述过一个 `permissions.auditRetentionDays` 选项，它并不存在；如需限制增长，请用 SQL 或数据库自身工具清理。
