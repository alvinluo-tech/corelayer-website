title: Revisar el Registro de Auditoria
description: Entiende y trabaja con el registro de auditoria del Permission Guard.
---

Cada decision de ejecucion de herramienta en CoreLayer queda registrada. Esta guia muestra como consultar y leer las entradas de auditoria.

## Acceder a los Registros

Las entradas se sirven por `GET /api/audit` y se muestran en el Centro de Control. Son un recurso distinto de las aprobaciones (`/api/approvals`) y del event log (`/api/events`).

## Formato de Entrada

Una entrada registra:

```text
createdAt          2026-10-21T14:32:01Z
actor              jarvis
action             tool.execute
resource           filesystem:write /workspace/README.md
riskLevel          high
permissionDecision confirm
confirmedByUser    true
result             success
metadata           { ... }
```

## Filtrar Registros

`GET /api/audit` acepta:

- `actor` — quien realizo la accion
- `action` — que se realizo
- `riskLevel` — `low` | `medium` | `high` | `critical`
- `since` — limite inferior de timestamp ISO
- `limit` / `offset` — paginacion

La respuesta es `{ entries, total, count }`.

## Casos de Uso Comunes

### Revision de Seguridad

Comprueba que acciones de alto riesgo se aprobaron:

1. Consulta `GET /api/audit?riskLevel=high&since=2026-10-01T00:00:00Z`
2. Revisa `resource` y `metadata` de cada entrada
3. Confirma que `confirmedByUser` es `true` donde esperabas una decision manual

### Depuracion

Encuentra por que una tool call no se ejecuto:

1. Filtra por `action`
2. Revisa `permissionDecision` — `deny` significa que la politica la bloqueo
3. Cruza el run id con `GET /api/runs/:id/events`

### Cumplimiento

Genera un registro de acciones que cambian estado:

1. Consulta con `riskLevel=high` y luego repite con `riskLevel=critical`
2. Exporta las entradas devueltas
3. Revisa cada entrada con `confirmedByUser: false` — se decidieron automaticamente

## Retencion de Registros

No hay opcion de retencion. Las entradas viven en la tabla `audit_log` de la base de datos configurada mientras las conserves. Una version anterior de esta pagina documentaba `permissions.auditRetentionDays`, que no existe; depura con SQL o las herramientas de tu base de datos si necesitas limitar el crecimiento.
