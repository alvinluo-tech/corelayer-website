CoreLayer 中每一次工具執行決定都會被記錄。本指南展示如何查詢與解讀稽核條目。

## 存取稽核日誌

稽核條目由 `GET /api/audit` 提供，並在控制中心展示。它與核准（`/api/approvals`）以及事件日誌（`/api/events`）是彼此獨立的資源。

## 日誌條目格式

一筆記錄包含：

```text
createdAt          2026-10-21T14:32:01Z
actor              jarvis
action             tool.execute
resource           filesystem:write /workspace/README.md
riskLevel          high
permissionDecision confirm
confirmedByUser    true
result             success
metadata           { ... }
```

## 篩選日誌

`GET /api/audit` 支援：

- `actor` — 誰執行了該動作
- `action` — 執行了什麼
- `riskLevel` — `low` | `medium` | `high` | `critical`
- `since` — ISO 時間下界
- `limit` / `offset` — 分頁

回應為 `{ entries, total, count }`。

## 常見使用情境

### 安全檢視

查看哪些高風險動作被核准：

1. 查詢 `GET /api/audit?riskLevel=high&since=2026-10-01T00:00:00Z`
2. 逐筆檢視 `resource` 與 `metadata`
3. 確認你期望人工決定的地方 `confirmedByUser` 為 `true`

### 除錯

找出某個工具呼叫為何沒有執行：

1. 按 `action` 篩選
2. 檢視 `permissionDecision`——`deny` 表示被策略攔截
3. 用 `GET /api/runs/:id/events` 交叉核對 run id

### 合規

產生狀態變更紀錄：

1. 先用 `riskLevel=high` 查詢，再用 `riskLevel=critical` 查詢
2. 匯出回傳的條目
3. 檢視所有 `confirmedByUser: false` 的條目——它們是被自動決定的

## 日誌保留

沒有保留期設定。條目一直存放在所設定資料庫的 `audit_log` 表中。本檔案早期版本描述過一個 `permissions.auditRetentionDays` 選項，它並不存在；如需限制成長，請用 SQL 或資料庫自身工具清理。
