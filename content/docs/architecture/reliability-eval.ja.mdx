---
title: 信頼性評価
description: CoreLayer がエージェントへの変更で本当に良くなったかをどう判断するか。
---

多くのエージェント変更は単発の実行では改善に見えます。CoreLayer は評価ハーネスを同梱し、その主張を検証できるようにします：`daemon/src/eval` はコーパスに対してコーディングエージェントを繰り返し実行し、最高の 1 回ではなく**一貫性**を報告します。

ハーネスは **`pnpm test` には含まれません** — 試行ごとに実際のモデル呼び出しを消費します。

## 何を測るか

| 指標 | 存在理由 |
|------|---------|
| **pass^k** | **すべての**試行で成功したタスクの割合。pass@k より厳しく、無人運用で本当に見るべき数字。 |
| **偽陽性 / 偽陰性** | 実行器が成功と主張したがチェックが失敗した（または逆）試行。ハーネスとエージェントがなぜ食い違うかを説明する。 |
| **実行器ステータス** | `succeeded`、`failed`、`cancelled`、`timed-out`。 |
| **無効試行（Voided）** | 環境障害（クォータ、接続拒否、プロバイダー 5xx）は比率から除外され、エージェントの失敗として数えられない。3 回連続で実行全体を停止。 |
| **コスト** | `tokens/attempt` と `tokens/success`。成功率が上がってもコストが倍なら改善ではない。 |

## 実行

```powershell
cd daemon
$env:ANTHROPIC_MODEL='<model>'
$env:ANTHROPIC_BASE_URL='http://127.0.0.1:8791'
$env:ANTHROPIC_AUTH_TOKEN='sk-...'
npx tsx src/eval/cli.ts --corpus src/eval/corpora/core.json --k 3
```

ハーネスには 2 つのコーパスが同梱されます：`core`（単一ファイルの作成・編集・デバッグ・削除・リネーム）と `holdout`（多段の調整、バイト単位の範囲規律、抑制、事実の捏造の拒否）。意図的に別々に採点します。

## ペア比較

`--compare NAME=VALUE` は同じコーパスを 2 回（変数なし、あり）実行し、ペア比較の判定を出します：

| 判定 | 意味 |
|------|------|
| `improved` | 全体が許容差を超え、かつ個別タスクが一切退歩していない |
| `regressed` | 全体が下降 |
| `mixed` | 平均は上がったが、タスクが信頼性を失った |
| `unchanged` | すべて許容帯の中 |

`mixed` は集約ゲートが見えない失敗モードです：平均では「信頼性向上」しながら、以前動いていたタスクを壊すケース。改善として報告してはいけません。

## 採用ルール

エージェントの挙動を変える変更（リフレクションループ、プロンプト調整、新しいゲート）は、ペア実行で次を満たす場合のみ既定にできます：

1. 判定が `improved`（`mixed` でも `unchanged` でもない）
2. 信頼性を失ったタスクがない
3. `tokens/success` の上昇が約 20% 以内
4. 再実行しても (1)–(3) を満たす

いずれかを満たさなければ既定はオフのまま。リフレクションループはこのルールに従い、既定は**オフ**です。

## ベースライン

2026-10-21 の `deepseek-v4.1-flash` 実行時点：

```text
core, k = 3        pass^3 = 100.0%   偽陽性 0 / 偽陰性 0
holdout, k = 1     pass^1 = 100.0%   偽陽性 0 / 偽陰性 0
```

コーパスは回帰検出器であり、スコアボードではありません。価値は次の変更で赤くなった行にあります。
