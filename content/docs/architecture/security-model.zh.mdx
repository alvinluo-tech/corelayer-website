title: 安全模型
description: CoreLayer 如何决定 Agent 能做什么、如何征求同意，以及如何记录决定。
---

CoreLayer 的前提假设是：被提示的模型终会出错，MCP 服务器可能是恶意的，编码 Agent 可能执行意料之外的命令。因此安全机制不依赖模型自我约束，而是在不读取提示词的代码层强制执行。

## 原则

1. **本地优先** — 除非你显式启用云存储，状态留在本机。
2. **顶层默认拒绝** — `critical` 风险默认被拒绝，除非有显式的审批或授权。
3. **风险靠声明** — 工具风险在注册时指定，绝不从工具名或参数推断。
4. **委派单调收窄** — 子运行只能收窄父运行的权限，不能放大。
5. **一切可归因** — 每次执行写审计记录，每次运行写事件。

## 强制层

| 层 | 强制的规则 |
|----|-----------|
| 权限守卫 | 风险 → 策略（`auto` / `notify` / `confirm` / `deny`） |
| 审批服务 | 挂起运行、持久化请求、决定后恢复 |
| 委派边界 | 路径范围、工具集、测试命令、超时、执行器与模型绑定 |
| 路径策略 | 编码运行可触碰哪些文件，按 worktree 解析 |
| Worktree 隔离 | 每次编码运行在自己的 git worktree 中写入，而非你的工作区 |
| 质量门禁 / 仲裁 | 证据不足以支撑“完成”时拒绝交付 |
| 审计 + 事件日志 | 记录谁做了什么、风险几何、返回了什么 |

## 风险等级与默认策略

四个等级是 `low`、`medium`、`high`、`critical`，默认策略：

| 风险 | 默认动作 | 含义 |
|------|----------|------|
| `low` | `auto` | 静默执行 |
| `medium` | `notify` | 执行并提示 |
| `high` | `confirm` | 挂起并等待人工决定 |
| `critical` | `deny` | 拒绝，除非已有显式授权 |

按应用的覆盖可以收紧或放宽某一级（例如 `write: false` 会把 `medium` 变为 `confirm`、`high` 变为 `deny`）。

会派生工作的工具显式声明为 `high`：`dispatch_agent`、`run_task_graph`、以及会话清理类工具。`dispatch_agent` 这个名字不含任何“危险词”，这正是风险不能靠推断的原因。

## 人在回路审批

```text
工具调用或执行器请求
  → 持久化审批请求（动作摘要、风险、范围）
  → 挂起运行
  → 界面展示请求：批准 / 拒绝 / 记住
  → 记录决定；恢复或终止运行
```

- 审批是持久化的，守护进程重启后待决定请求不会丢失。
- 支持批量批准/拒绝和过期清理，用于无人值守期累积的队列。
- “记住”会基于动作摘要生成权限记忆，同一动作不再重复询问。

配置见 [权限](/docs/configuration/permissions)，端点见 [API 参考](/docs/reference/api-endpoints#approvals)。

## 数据安全

本地状态分布在 CoreLayer 主目录下的六个分区：

| 分区 | 内容 | 敏感性 |
|------|------|--------|
| `config/` | `config.json`、`routing.json` | 无密钥，可安全同步 |
| `security/` | `credentials.json` | 密钥；POSIX 下 `0600` |
| `memory/` | `USER.md`、`MEMORY.md`、`journal/`、`dreams/` | 个人数据 |
| `storage/` | SQLite 数据库 | 个人数据 |
| `worktrees/` | `active/`、`snapshots/` | 正在执行的代码 |
| `cache/` | 符号图、MCP schema、委派管道 | 可丢弃 |

API Key 的解析顺序：环境变量 → `security/credentials.json` → 供应商默认值（无密钥）。密钥只会发往你配置的那家供应商。

启用云存储（Supabase）或自托管 PostgreSQL 后，数据会离开本机。Supabase 传输走 HTTPS，项目与访问策略由你掌控。

## 网络面

- 守护进程只监听回环。`/api/runtime/shutdown` 拒绝非回环对端。
- 出站连接仅限已配置的模型供应商、已配置的 MCP 服务器与你配置的数据库。
- 无遥测、无统计、无回连。

## 威胁模型

| 威胁 | 缓解 |
|------|------|
| 模型请求破坏性工具 | 声明式风险 + 策略；`high` 需确认，`critical` 直接拒绝 |
| 工具输出中的提示注入 | 工具结果是数据而非指令；副作用仍受审批约束 |
| 恶意或被攻陷的 MCP 服务器 | 每个工具带风险等级注册，高风险调用被拦截并审计 |
| 编码 Agent 越出范围 | Worktree 隔离 + 路径策略 + 收窄后的委派边界 |
| Agent 通过委派绕过限制 | 边界只会收窄：路径取交集、工具取交集、检查只增不减、执行器/模型不可更换 |
| 子进程无证据宣称成功 | 完成策略 + 质量门禁；对抗式仲裁只有在存在证据时才判定 |
| 其他主机悄悄访问守护进程 | 仅回环绑定，关闭接口校验对端 |

## 已知限制

- **Computer control 未启用。** 其执行路径是空壳且未注册，请勿依赖屏幕或输入自动化。
- **委派边界的上限取决于执行器。** 不遵守路径策略的执行器，真正起作用的边界是 worktree 与事后 diff。
- **`mcp-servers.json` 与 SQLite 路径仍使用旧位置**，因此上表的分区适用于 `config.json`、凭据、记忆、worktree 与缓存，而非所有文件。
