---

本頁追蹤三條關鍵流程：一次對話回合、回合中的一次工具呼叫，以及被派發後獨立於對話繼續執行的 Run。

## 對話回合

```text
1. 使用者在聊天面板送出訊息
2. 前端 → Tauri IPC → 守護行程 HTTP
     POST /api/conversations/:id/messages/stream   （或 POST /api/chat/stream）
3. agent 執行階段組裝上下文：
     - 會話歷史（按會話、支援分支）
     - 從 memory 執行階段檢索的長期記憶
     - 核心工具集，以及路由按需選出的工具
4. 模型閘道解析目前供應商/模型並發起串流呼叫
     （Vercel AI SDK v6；步進控制在 prepareStep 內完成）
5. 每個步驟可以：
     - 輸出文字 → 串流送達介面
     - 請求工具呼叫 → 進入下方的工具呼叫流程
6. 熔斷器與步數預算決定本回合繼續還是停止
7. 完成策略與品質閘門決定結果是否可交付
8. 最終訊息持久化，SSE 串流關閉
```

## 工具呼叫

```text
模型請求工具呼叫
  → 工具註冊中心解析工具（native / MCP / skill）
  → 權限守衛讀取工具上宣告的風險（不靠推斷）
  → 策略判定：
      auto    → 直接執行
      notify  → 執行並提示
      confirm → 建立審批請求，掛起執行，等待決定後恢復
      deny    → 阻止並記錄
  → 執行
  → 寫入稽核（操作者、動作、風險、決定、結果）
  → 將結果回傳模型
```

審批是持久化的，而非只存在於記憶體中：待決定請求在守護行程重啟後仍然存在，使用者做出決定後由恢復服務繼續。

## 派發的執行

```text
使用者目標 / 委派任務
  → run dispatcher 校驗邊界（委派只能收窄）
  → 佇列項目佔用槽位（併發按資源類別設上限）
  → coding 執行階段建立 git worktree
  → 執行器轉接器啟動子 Agent（ACP）
  → 能力探測：ready / needs_auth / unreachable
  → 子行程串流輸出事件 → 事件映射 → 事件日誌
  → diff 與產物寫入 run 記錄
  → 品質閘門 / 對抗式仲裁（若啟用）
  → 完成策略：通過 → 交付分支；失敗 → 帶原因失敗
```

每次狀態轉移都會寫入 `agent_run` 事件，因此 `GET /api/runs/:id/events` 可以在事後重建一次執行，也正因如此執行可以按 id 取消或重試。

## MCP 連線

```text
1. 守護行程從 mcp-servers.json 讀取伺服器定義
2. 啟動子行程（stdio）或透過 HTTP/SSE 連線
3. 完成 MCP initialize 握手
4. 讀取工具清單，按伺服器風險策略逐個註冊
5. 工具對路由與模型可用
6. 斷線後標記為 disconnected，可重啟
```

## 儲存寫入

```text
路由或執行階段 → 倉儲層（SQLite / Supabase / PostgreSQL）
  → schema 校驗
  → 寫入
  → （若為事件）同時追加到事件日誌
```

儲存模式在啟動時從 `storage.json` 讀取（`local`、`cloud`、`postgres`）。詳見 [儲存](/docs/configuration/storage)。

## 語音回合

```text
喚醒詞 → 開啟麥克風 → ASR 串流輸出臨時與最終轉寫
  → 最終轉寫與鍵盤輸入走完全相同的對話管線
  → 回覆串流回傳；TTS 按句播報
  → 打斷：播放中說話會中斷音訊並回到 ASR
```
