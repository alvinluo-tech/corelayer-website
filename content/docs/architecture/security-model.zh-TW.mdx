title: 安全模型
description: CoreLayer 如何決定 Agent 能做什麼、如何徵求同意，以及如何記錄決定。
---

CoreLayer 的前提假設是：被提示的模型終會出錯，MCP 伺服器可能是惡意的，編碼 Agent 可能執行意料之外的指令。因此安全機制不依賴模型自我約束，而是在不讀取提示詞的程式碼層強制執行。

## 原則

1. **本地優先** — 除非你顯式啟用雲端儲存，狀態留在本機。
2. **頂層預設拒絕** — `critical` 風險預設被拒絕，除非有顯式的審批或授權。
3. **風險靠宣告** — 工具風險在註冊時指定，絕不從工具名或參數推斷。
4. **委派單調收窄** — 子執行只能收窄父執行的權限，不能放大。
5. **一切可歸因** — 每次執行寫稽核記錄，每次執行寫事件。

## 強制層

| 層 | 強制的規則 |
|----|-----------|
| 權限守衛 | 風險 → 策略（`auto` / `notify` / `confirm` / `deny`） |
| 審批服務 | 掛起執行、持久化請求、決定後恢復 |
| 委派邊界 | 路徑範圍、工具集、測試指令、逾時、執行器與模型綁定 |
| 路徑策略 | 編碼執行可觸碰哪些檔案，按 worktree 解析 |
| Worktree 隔離 | 每次編碼執行在自己的 git worktree 中寫入，而非你的工作區 |
| 品質閘門 / 仲裁 | 證據不足以支撐「完成」時拒絕交付 |
| 稽核 + 事件日誌 | 記錄誰做了什麼、風險幾何、回傳了什麼 |

## 風險等級與預設策略

四個等級是 `low`、`medium`、`high`、`critical`，預設策略：

| 風險 | 預設動作 | 含義 |
|------|----------|------|
| `low` | `auto` | 靜默執行 |
| `medium` | `notify` | 執行並提示 |
| `high` | `confirm` | 掛起並等待人工決定 |
| `critical` | `deny` | 拒絕，除非已有顯式授權 |

按應用的覆寫可以收緊或放寬某一級（例如 `write: false` 會把 `medium` 變為 `confirm`、`high` 變為 `deny`）。

會派生工作的工具顯式宣告為 `high`：`dispatch_agent`、`run_task_graph`、以及會話清理類工具。`dispatch_agent` 這個名字不含任何「危險詞」，這正是風險不能靠推斷的原因。

## 人在迴路審批

```text
工具呼叫或執行器請求
  → 持久化審批請求（動作摘要、風險、範圍）
  → 掛起執行
  → 介面展示請求：批准 / 拒絕 / 記住
  → 記錄決定；恢復或終止執行
```

- 審批是持久化的，守護行程重啟後待決定請求不會遺失。
- 支援批次批准/拒絕與過期清理，用於無人值守期累積的佇列。
- 「記住」會基於動作摘要產生權限記憶，同一動作不再重複詢問。

設定見 [權限](/docs/configuration/permissions)，端點見 [API 參考](/docs/reference/api-endpoints#approvals)。

## 資料安全

本地狀態分布在 CoreLayer 主目錄下的六個分區：

| 分區 | 內容 | 敏感性 |
|------|------|--------|
| `config/` | `config.json`、`routing.json` | 無密鑰，可安全同步 |
| `security/` | `credentials.json` | 密鑰；POSIX 下 `0600` |
| `memory/` | `USER.md`、`MEMORY.md`、`journal/`、`dreams/` | 個人資料 |
| `storage/` | SQLite 資料庫 | 個人資料 |
| `worktrees/` | `active/`、`snapshots/` | 正在執行的程式碼 |
| `cache/` | 符號圖、MCP schema、委派管道 | 可丟棄 |

API Key 的解析順序：環境變數 → `security/credentials.json` → 供應商預設值（無密鑰）。密鑰只會發往你設定的那家供應商。

啟用雲端儲存（Supabase）或自架 PostgreSQL 後，資料會離開本機。Supabase 傳輸走 HTTPS，專案與存取策略由你掌控。

## 網路面

- 守護行程只監聽回環。`/api/runtime/shutdown` 拒絕非回環對端。
- 出站連線僅限已設定的模型供應商、已設定的 MCP 伺服器與你設定的資料庫。
- 無遙測、無統計、無回連。

## 威脅模型

| 威脅 | 緩解 |
|------|------|
| 模型請求破壞性工具 | 宣告式風險 + 策略；`high` 需確認，`critical` 直接拒絕 |
| 工具輸出中的提示注入 | 工具結果是資料而非指令；副作用仍受審批約束 |
| 惡意或被攻陷的 MCP 伺服器 | 每個工具帶風險等級註冊，高風險呼叫被攔截並稽核 |
| 編碼 Agent 越出範圍 | Worktree 隔離 + 路徑策略 + 收窄後的委派邊界 |
| Agent 透過委派繞過限制 | 邊界只會收窄：路徑取交集、工具取交集、檢查只增不減、執行器/模型不可更換 |
| 子行程無證據宣稱成功 | 完成策略 + 品質閘門；對抗式仲裁只有在存在證據時才判定 |
| 其他主機悄悄存取守護行程 | 僅回環綁定，關閉介面校驗對端 |

## 已知限制

- **Computer control 未啟用。** 其執行路徑是空殼且未註冊，請勿依賴螢幕或輸入自動化。
- **委派邊界的上限取決於執行器。** 不遵守路徑策略的執行器，真正起作用的邊界是 worktree 與事後 diff。
- **`mcp-servers.json` 與 SQLite 路徑仍使用舊位置**，因此上表的分區適用於 `config.json`、憑證、記憶、worktree 與快取，而非所有檔案。
