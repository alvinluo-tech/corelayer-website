---
title: 可靠性评测
description: CoreLayer 如何判断一次针对 Agent 的改动是否真的让它变好。
---

大多数 Agent 改动在单次运行里看起来都是改进。CoreLayer 提供评测框架，让这个说法可以被检验：`daemon/src/eval` 会针对语料反复运行编码 Agent，报告的是**一致性**，而不是最好的一次。

该框架**不**属于 `pnpm test`——每次尝试都消耗一次真实的模型调用。

## 度量什么

| 指标 | 为什么存在 |
|------|-----------|
| **pass^k** | 在**每一次**尝试中都成功的任务比例。严格难于 pass@k，是无人值守场景真正该看的数字。 |
| **假阳性 / 假阴性** | 执行器声称成功但检查失败（或相反）的尝试。用于解释框架与 Agent 为何不一致。 |
| **执行器状态** | `succeeded`、`failed`、`cancelled`、`timed-out`。 |
| **作废尝试（Voided）** | 环境故障（配额、连接被拒、供应商 5xx）不计入比率，而不是算成 Agent 失败。连续三次会终止整轮。 |
| **成本** | `tokens/attempt` 与 `tokens/success`；成功率提升但开销翻倍，不算改进。 |

## 运行

```powershell
cd daemon
$env:ANTHROPIC_MODEL='<model>'
$env:ANTHROPIC_BASE_URL='http://127.0.0.1:8791'
$env:ANTHROPIC_AUTH_TOKEN='sk-...'
npx tsx src/eval/cli.ts --corpus src/eval/corpora/core.json --k 3
```

框架自带两套语料：`core`（单文件写、改、调试、删除、重命名）与 `holdout`（多步协同、字节级范围纪律、克制、拒绝编造事实）。二者分开评分是有意为之。

## 配对比较

`--compare NAME=VALUE` 会把同一语料跑两遍——变量未设置一次、设置一次——并给出配对结论：

| 结论 | 含义 |
|------|------|
| `improved` | 总体超过容差，且没有任何单个任务退步 |
| `regressed` | 总体下降 |
| `mixed` | 均值上升，但有任务失去可靠性 |
| `unchanged` | 全部落在容差带内 |

`mixed` 正是聚合门槛看不见的失败模式：平均“提升可靠性”的同时弄坏了某个原本可用的任务。它不能被报告为改进。

## 准入规则

改变 Agent 行为的改动（反思循环、提示词调整、新门禁）只有在配对运行满足以下条件时才能成为默认：

1. 结论为 `improved`——不是 `mixed`，也不是 `unchanged`
2. 没有任务失去可靠性
3. `tokens/success` 上升不超过约 20%
4. 复跑一次仍满足 (1)–(3)

任一条件不满足，改动保持默认关闭。反思循环遵循此规则，默认**关闭**。

## 基线

截至 2026-10-21 使用 `deepseek-v4.1-flash` 的运行结果：

```text
core, k = 3        pass^3 = 100.0%   0 假阳性 / 0 假阴性
holdout, k = 1     pass^1 = 100.0%   0 假阳性 / 0 假阴性
```

语料是回归探测器，不是排行榜。它的价值在于下一次改动后出现的那一行红色。
