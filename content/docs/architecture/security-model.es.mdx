---
title: Modelo de Seguridad
description: Como CoreLayer decide que puede hacer un agente, como lo pregunta y como registra la respuesta.
---

CoreLayer asume que un modelo con prompt acabara equivocandose, que un servidor MCP puede ser hostil y que un agente de codigo puede ejecutar un comando no previsto. Por eso la seguridad se aplica por debajo del modelo, en codigo que no lee el prompt.

## Principios

1. **Local-first** — el estado vive en tu maquina salvo que habilites explicitamente el almacenamiento en la nube.
2. **Denegar por defecto en la cima** — el riesgo `critical` se deniega salvo que un flujo de aprobacion diga lo contrario.
3. **Riesgo declarado** — el nivel de riesgo de una herramienta se fija al registrarla; nunca se infiere del nombre ni de los argumentos.
4. **Delegacion monotona** — una ejecucion hija puede estrechar los permisos de su padre, nunca ampliarlos.
5. **Todo es atribuible** — cada ejecucion escribe auditoria y cada ejecucion escribe eventos.

## Capas de aplicacion

| Capa | Aplica |
|------|--------|
| Permission Guard | riesgo → politica (`auto` / `notify` / `confirm` / `deny`) |
| Servicio de aprobaciones | suspende la ejecucion, persiste la solicitud, reanuda tras la decision |
| Limites de delegacion | alcance de rutas, conjunto de herramientas, comandos de test, timeout, fijacion de ejecutor y modelo |
| Politica de rutas | que archivos puede tocar una ejecucion de codigo, resuelto contra el worktree |
| Aislamiento por worktree | cada ejecucion de codigo escribe en su propio worktree git, no en tu checkout |
| Quality gates / juez | se niega a entregar una ejecucion cuya evidencia no sostiene "terminado" |
| Audit + event log | registra quien hizo que, con que riesgo y que volvio |

## Niveles de riesgo y politica por defecto

Los cuatro niveles son `low`, `medium`, `high`, `critical`. Politica por defecto:

| Riesgo | Accion por defecto | Significado |
|--------|--------------------|-------------|
| `low` | `auto` | Ejecutar en silencio |
| `medium` | `notify` | Ejecutar y notificar |
| `high` | `confirm` | Suspender y esperar decision humana |
| `critical` | `deny` | Bloquear salvo concesion explicita |

Las anulaciones por app pueden endurecer o relajar un nivel (por ejemplo `write: false` convierte `medium` en `confirm` y `high` en `deny`).

Las herramientas que generan trabajo declaran `high` de forma explicita: `dispatch_agent`, `run_task_graph` y la limpieza destructiva de conversaciones. Un nombre como `dispatch_agent` no contiene ninguna palabra de riesgo, y precisamente por eso el riesgo no se infiere.

## Aprobaciones human-in-the-loop

```text
Tool call o solicitud de permiso de un ejecutor
  → se persiste la solicitud (digest de accion, riesgo, alcance)
  → se suspende la ejecucion
  → la UI muestra la solicitud; el usuario aprueba / deniega / recuerda
  → se registra la decision; la ejecucion se reanuda o falla
```

- Las aprobaciones se almacenan, asi que una decision pendiente sobrevive al reinicio del daemon.
- Se soportan aprobacion/denegacion por lote y expiracion de obsoletas para colas sin atencion.
- "Recordar" crea una memoria de permiso ligada al digest de la accion, asi la misma accion no se pregunta dos veces.

Ver [Permisos](/docs/configuration/permissions) para la configuracion y [API de Aprobaciones](/docs/reference/api-endpoints#approvals) para los endpoints.

## Seguridad de datos

El estado local se divide en seis zonas bajo el directorio home de CoreLayer:

| Zona | Contenido | Sensibilidad |
|------|-----------|--------------|
| `config/` | `config.json`, `routing.json` | Sin secretos, seguro para sincronizar |
| `security/` | `credentials.json` | Secretos; `0600` en POSIX |
| `memory/` | `USER.md`, `MEMORY.md`, `journal/`, `dreams/` | Personal |
| `storage/` | bases SQLite | Personal |
| `worktrees/` | `active/`, `snapshots/` | Codigo en ejecucion |
| `cache/` | grafos de simbolos, esquemas MCP, pipes de delegacion | Desechable |

Las claves API se resuelven en este orden: variable de entorno → `security/credentials.json` → valor por defecto del proveedor sin clave. Una clave solo se envia al proveedor que configuraste.

Al habilitar almacenamiento en la nube (Supabase) o PostgreSQL propio, los datos salen de la maquina. Supabase usa HTTPS; tu eres dueno del proyecto y de sus politicas.

## Superficie de red

- El daemon escucha en loopback. `/api/runtime/shutdown` rechaza peers que no sean loopback.
- Las conexiones salientes son solo a proveedores configurados, servidores MCP configurados y tu base de datos.
- Sin telemetria, analitica ni llamadas a casa.

## Modelo de amenazas

| Amenaza | Mitigacion |
|---------|------------|
| El modelo pide una herramienta destructiva | Riesgo declarado + politica; `high` requiere confirmacion, `critical` se deniega |
| Inyeccion de prompt via salida de herramienta | La salida de herramientas es dato, no instruccion; la aprobacion sigue controlando efectos |
| Servidor MCP malicioso o comprometido | Cada herramienta se registra con riesgo; las llamadas peligrosas se controlan y auditan |
| Un agente de codigo se sale de su alcance | Aislamiento por worktree + politica de rutas + limites de delegacion estrechados |
| Un agente delega para saltarse sus limites | Los limites solo estrechan: rutas y herramientas se intersectan, las comprobaciones se suman, ejecutor/modelo no cambian |
| El hijo reporta exito sin evidencia | Politica de completion + quality gates; el juez adversarial exige evidencia |
| Acceso silencioso desde otro host | Bind solo loopback y verificacion de peer al apagar |

## Limites conocidos

- **Computer control no esta activo.** Su ruta de ejecucion es un stub y no esta registrado; no dependas de automatizacion de pantalla o entrada.
- **Los limites de delegacion valen lo que valga el ejecutor.** Un ejecutor que no respeta la politica de rutas tiene como limite real el worktree y el diff posterior.
- **`mcp-servers.json` y la ruta de SQLite siguen resolviendose en ubicaciones heredadas**, asi que la tabla de seis zonas aplica a `config.json`, credenciales, memoria, worktrees y cache, no a todos los archivos.
