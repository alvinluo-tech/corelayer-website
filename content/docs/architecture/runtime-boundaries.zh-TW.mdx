CoreLayer 將介面、桌面外殼、守護行程與外部行程相互隔離，使某一層的故障無法悄悄升級成另一層的問題。

## 邊界模型

```text
Webview UI（React）
  ║ Tauri IPC —— 僅限顯式註冊的指令
  ╚═► Tauri 外殼（Rust）
      ║ HTTP —— 僅限回環
      ╚═► Node.js 守護行程（Hono）
          ║ 行程內模組呼叫（public-api 模組）
          ╠═► 共享套件
          ║ 子行程 / 網路
          ╠═► ACP 執行器行程（Claude Code、Codex、OpenCode）
          ╠═► MCP 伺服器（stdio 子行程或 HTTP/SSE）
          ╚═► 資料庫（SQLite 檔案、Supabase、PostgreSQL）
```

## 跨邊界規則

| 邊界 | 規則 |
|------|------|
| UI → Tauri | 僅限註冊指令；不直接存取檔案系統或網路 |
| Tauri → 守護行程 | 回環 HTTP；連接埠在啟動時確定並由 `/api/runtime/status` 上報 |
| 守護行程 → 套件 | 經各執行階段 `public-api.ts` 匯入，禁止直接進入內部模組 |
| 守護行程 → 執行器 | 在 git worktree 中的子行程，綁定模型/執行器並受收窄後的邊界約束 |
| 守護行程 → MCP 伺服器 | stdio 子行程或遠端 HTTP/SSE；上報的每個工具都註冊並標註風險 |
| 守護行程 → 資料庫 | 只經倉儲層；路由不直接查詢資料庫 |

其中一條由機器強制：若某個 HTTP 路由繞過 `public-api.ts` 直接存取執行階段內部，匯入邊界測試會讓建置失敗。

## UI ↔ Tauri

- 兩端都有型別（TypeScript ↔ Rust 結構體）
- 載荷為 JSON
- 呼叫非同步；介面不會阻塞等待守護行程啟動

## Tauri ↔ 守護行程

- HTTP，僅限回環。`/api/runtime/shutdown` 還會拒絕非回環對端。
- 串流對話與執行進度使用 SSE。
- 外殼掌管守護行程生命週期：啟動、健康檢查、崩潰重啟、結束時終止。

## 守護行程 ↔ 執行器

編碼工作不在守護行程內執行。coding 執行階段透過轉接器（見 [編碼執行器轉接器](/docs/guides/coding-executors)）在隔離的 git worktree 中啟動外部 Agent，只回讀結構化事件、產物與 diff。子行程能做什麼在派發時就由[委派邊界](/docs/architecture/executor-governance#delegation-bounds)固定，子行程無法自行放寬。

## 為什麼重要

- **隔離** — 行為異常的執行器只能破壞自己的工作區
- **可歸因** — 每次狀態變化都有 run id、操作者與稽核記錄
- **可替換** — 供應商、執行器或儲存後端可獨立替換
- **可測試** — 邊界由測試強制，而不只靠約定
