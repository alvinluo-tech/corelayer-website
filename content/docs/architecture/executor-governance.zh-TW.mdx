---
title: 執行器治理
description: CoreLayer 如何把「裸跑」的編碼 Agent 變成受監管的執行器。
---

Claude Code、Codex、OpenCode 能力很強，但直接對著 shell 執行就是一個無界行程：能寫任何位置、執行任何指令、匯報任何結論。CoreLayer 不重寫它們，而是在外面包一層治理，並保留「這次工作是否可接受」的判斷權。

## 管線

```text
派發請求
  → 校驗委派邊界（在任何行程建立前就拒絕）
  → 分配佇列槽位
  → 建立隔離的 git worktree
  → 能力探測（acpx <agent> sessions ensure）
      ready        → 繼續
      needs_auth   → 告知使用者缺少哪個登入
      unreachable  → 回報啟動錯誤，不空轉
  → 綁定執行器與模型後啟動
  → 將子行程事件流映射為執行事件
  → 擷取 diff 與產物
  → 品質閘門 → 對抗式仲裁（若啟用）
  → 完成策略：交付、重試，或帶原因失敗
```

## 委派邊界

一次將工作委派給子執行的執行，只能**收窄**自己本來能做的事：

| 邊界 | 收窄規則 |
|------|----------|
| `allowedPaths` | 與父層範圍做 glob 交集；越出儲存庫的請求直接拒絕 |
| `testCommands` | 只增不減——子執行不能丟掉父層要求的檢查 |
| `requiredArtifactTypes` | 只增不減 |
| `timeoutMs` | `min(子, 父, 30 分鐘)`，下限 30 秒 |
| `allowedTools` | 取交集——子執行工具只能更少，不能持有父層沒有的工具 |
| `executor` / `executorModel` | 綁定；子執行不能更換執行器或模型 |

兩個需要說明的後果：父層路徑範圍為空意味著「尚未受限」，此時子請求成為第一道約束；委派提示詞超過 8000 字元會被拒絕——委派是交代一件事，不是傳文件。

## 隔離

- 每次編碼執行在 `worktrees/active` 下擁有獨立 git worktree，封存快照寫入 `worktrees/snapshots`。
- 路徑策略在正規化之後再判定所收到的路徑，因此 Windows 分隔符與 `git status` 前綴無法讓合法路徑看起來像越界。
- 交付物是可審查的分支，而不是對你工作區的直接寫入。

## 證據而非聲明

執行器說「完成了」不構成證據。CoreLayer 把完成當作可檢驗的聲明：

- **完成策略** — 任務中的 `test: <指令>`、`artifact: <型別>`、`path: <glob>` 會被編譯成檢查項；自由文字條件保留為人工項，不會假裝已驗證。
- **品質閘門** — 某類任務的必需閘門未通過時不予交付。
- **對抗式仲裁** — 由獨立評審針對 diff 與任務目標判定，預設關閉（`adjudication.enabled = false`）。每次嘗試消耗一次模型呼叫，且只有在存在 diff 並真的執行過測試指令時才有證據可判。

## 能力協商

系統不假設執行器支援某項能力。能力探測會完成完整的 ACP 握手（`initialize` + `session/new`）但不送出提示回合，因此不消耗 token，並按啟動設定快取結果。這個區分很重要：「已安裝」無法告訴你 Agent 是就緒、缺登入，還是啟動指令壞了。

## 刻意不做的事

- 不對卡死的執行器無限重試：執行預算在兩側各生效一次，環境故障會被分類，而不是歸咎於 Agent。
- 不靜默放寬：子執行若請求未獲授權的模型或路徑，會在啟動前被拒絕。
- 不謊稱支援 computer control：該執行階段未註冊。
