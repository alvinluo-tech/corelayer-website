本ページでは重要な 3 つのフローを追います：会話ターン、そのターン内のツール呼び出し、そしてターンを越えて続くディスパッチ済みの実行です。

## 会話ターン

```text
1. ユーザーがチャットパネルからメッセージを送信
2. フロントエンド → Tauri IPC → デーモン HTTP
     POST /api/conversations/:id/messages/stream   （または POST /api/chat/stream）
3. agent ランタイムがコンテキストを組み立てる：
     - 会話履歴（会話単位、ブランチ対応）
     - memory ランタイムから取得した長期記憶
     - コアツール群、およびルーターが選んだオンデマンドツール
4. モデルゲートウェイが有効なプロバイダー/モデルを解決しストリーミング呼び出しを開く
     （Vercel AI SDK v6。ステップ制御は prepareStep 内で行う）
5. 各ステップは次のいずれか：
     - テキストを出力 → UI へストリーム
     - ツール呼び出しを要求 → 下記のツール呼び出しフローへ
6. ループブレーカーとステップ予算がターンの継続可否を決める
7. 完了ポリシーと品質ゲートが結果の受け入れ可否を決める
8. 最終メッセージを永続化し SSE ストリームを閉じる
```

## ツール呼び出し

```text
モデルがツール呼び出しを要求
  → ツールレジストリが解決（native / MCP / skill）
  → パーミッションガードがツール定義上のリスクを読む（推測しない）
  → ポリシー判定：
      auto    → 実行
      notify  → 実行して通知
      confirm → 承認リクエストを永続化し実行を停止、決定後に再開
      deny    → ブロックして記録
  → 実行
  → 監査を書き込む（実行者、アクション、リスク、決定、結果）
  → 結果をモデルへ返す
```

承認はメモリ上ではなく永続化されます。保留中のリクエストはデーモン再起動後も残り、ユーザーの決定後に再開サービスが続行します。

## ディスパッチされた実行

```text
ユーザーの目標 / 委譲タスク
  → run dispatcher が境界を検証（委譲は狭めるだけ）
  → キュー項目がスロットを取得（同時実行はリソース種別ごとに上限あり）
  → coding ランタイムが git worktree を作成
  → エグゼキューターアダプターが子エージェントを起動（ACP）
  → 機能プローブ：ready / needs_auth / unreachable
  → 子プロセスがイベントをストリーム → イベントマッパー → イベントログ
  → diff と成果物を run レコードへ取り込む
  → 品質ゲート / 敵対的ジャッジ（有効時）
  → 完了ポリシー：合格 → 納品ブランチ、不合格 → 理由付きで失敗
```

すべての状態遷移が `agent_run` イベントを書き込むため、`GET /api/runs/:id/events` で実行を事後再構成でき、id によるキャンセルや再試行も可能になります。

## MCP 接続

```text
1. デーモンが mcp-servers.json からサーバー定義を読み込む
2. 子プロセスを起動（stdio）または HTTP/SSE で接続
3. MCP initialize ハンドシェイク
4. ツール一覧を読み、サーバーのリスクポリシーで登録
5. ツールがルーターとモデルに利用可能になる
6. 切断時は disconnected と記録し、再起動可能
```

## ストレージ書き込み

```text
ルートまたはランタイム → リポジトリ（SQLite / Supabase / PostgreSQL）
  → スキーマ検証
  → 書き込み
  → （イベントの場合）イベントログにも追記
```

ストレージモードは起動時に `storage.json`（`local`、`cloud`、`postgres`）から読み取ります。詳細は [ストレージ](/docs/configuration/storage) を参照。

## 音声ターン

```text
ウェイクワード → マイク起動 → ASR が暫定/確定文字起こしをストリーム
  → 確定文字起こしはキーボード入力とまったく同じ会話パイプラインに入る
  → 応答をストリームし、TTS が文単位で読み上げる
  → バージイン：再生中に話すと音声を中断して ASR に戻る
```
