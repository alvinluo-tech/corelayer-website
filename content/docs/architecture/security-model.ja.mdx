---
title: セキュリティモデル
description: CoreLayer がエージェントの行動範囲、同意の求め方、決定の記録方法をどう決めるか。
---

CoreLayer の前提は「プロンプトされたモデルはいずれ間違える」「MCP サーバーは敵対的になり得る」「コーディングエージェントは意図しないコマンドを実行し得る」です。したがって安全性はモデルの自己抑制に頼らず、プロンプトを読まないコード層で強制します。

## 原則

1. **ローカルファースト** — クラウドストレージを明示的に有効化しない限り状態は手元に留まる。
2. **最上位は既定で拒否** — `critical` は明示的な承認・付与がない限り拒否される。
3. **リスクは宣言する** — ツールのリスクは登録時に指定し、名前や引数から推測しない。
4. **委譲は単調に狭める** — 子実行は親の権限を狭められるが広げられない。
5. **すべて帰属可能** — 実行ごとに監査記録、実行ごとにイベント。

## 強制レイヤー

| レイヤー | 強制する内容 |
|---------|-------------|
| パーミッションガード | リスク → ポリシー（`auto` / `notify` / `confirm` / `deny`） |
| 承認サービス | 実行の停止、リクエストの永続化、決定後の再開 |
| 委譲の境界 | パス範囲、ツール集合、テストコマンド、タイムアウト、エグゼキューター/モデル固定 |
| パスポリシー | コーディング実行が触れられるファイル。worktree に対して解決 |
| worktree 分離 | コーディング実行は自分の git worktree に書く（あなたの作業ツリーではなく） |
| 品質ゲート / ジャッジ | 証拠が「完了」を支持しない実行は納品しない |
| 監査 + イベントログ | 誰が何を、どのリスクで行い、何が返ったかを記録 |

## リスクレベルと既定ポリシー

4 段階は `low`、`medium`、`high`、`critical`。既定ポリシー：

| リスク | 既定アクション | 意味 |
|--------|----------------|------|
| `low` | `auto` | 静かに実行 |
| `medium` | `notify` | 実行して通知 |
| `high` | `confirm` | 停止して人間の決定を待つ |
| `critical` | `deny` | 明示的な付与がない限り拒否 |

アプリ単位の上書きで 1 段階だけ厳しくも緩くもできます（例：`write: false` で `medium` → `confirm`、`high` → `deny`）。

作業を派生させるツールは明示的に `high` を宣言します：`dispatch_agent`、`run_task_graph`、会話クリーンアップ系。`dispatch_agent` という名前には危険語が一切含まれませんが、まさにそれがリスク推測を使わない理由です。

## ヒューマン・イン・ザ・ループ承認

```text
ツール呼び出し / エグゼキューターの権限要求
  → 承認リクエストを永続化（アクションダイジェスト、リスク、範囲）
  → 実行を停止
  → UI がリクエストを表示：承認 / 拒否 / 記憶
  → 決定を記録し、実行を再開または失敗させる
```

- 承認は永続化されるため、デーモン再起動でも保留中の決定は失われません。
- 無人運用で溜まったキューのために、バッチ承認/拒否と期限切れ処理があります。
- 「記憶」はアクションダイジェスト単位の権限メモリを作り、同じアクションを二度尋ねません。

設定は [権限](/docs/configuration/permissions)、エンドポイントは [API リファレンス](/docs/reference/api-endpoints#approvals) を参照。

## データセキュリティ

ローカル状態は CoreLayer ホーム配下の 6 つのゾーンに分かれます：

| ゾーン | 内容 | 機密度 |
|--------|------|--------|
| `config/` | `config.json`、`routing.json` | 秘密なし。同期可能 |
| `security/` | `credentials.json` | 秘密。POSIX では `0600` |
| `memory/` | `USER.md`、`MEMORY.md`、`journal/`、`dreams/` | 個人データ |
| `storage/` | SQLite データベース | 個人データ |
| `worktrees/` | `active/`、`snapshots/` | 実行中のコード |
| `cache/` | シンボルグラフ、MCP スキーマ、委譲パイプ | 破棄可能 |

API キーの解決順は：環境変数 → `security/credentials.json` → プロバイダー既定値（キーなし）。キーは設定したプロバイダーにしか送られません。

クラウドストレージ（Supabase）やセルフホスト PostgreSQL を有効にするとデータはマシン外に出ます。Supabase の転送は HTTPS で、プロジェクトとアクセスポリシーはあなたが管理します。

## ネットワーク面

- デーモンはループバックのみをリッスン。`/api/runtime/shutdown` は非ループバックのピアを拒否。
- 外向き接続は設定済みのモデルプロバイダー、設定済みの MCP サーバー、設定済みのデータベースのみ。
- テレメトリ、解析、フォン・ホームはありません。

## 脅威モデル

| 脅威 | 緩和 |
|------|------|
| モデルが破壊的ツールを要求 | 宣言的リスク + ポリシー。`high` は確認、`critical` は拒否 |
| ツール出力経由のプロンプトインジェクション | ツール結果はデータであり命令ではない。副作用は承認で制御 |
| 悪意ある/侵害された MCP サーバー | 各ツールをリスク付きで登録。危険な呼び出しは制御・監査 |
| コーディングエージェントの範囲逸脱 | worktree 分離 + パスポリシー + 狭められた委譲境界 |
| 委譲で制限を迂回 | 境界は狭めるだけ：パスは積集合、ツールは積集合、チェックは加算のみ、実行器/モデルは変更不可 |
| 証拠なしの成功報告 | 完了ポリシー + 品質ゲート。敵対的ジャッジは証拠がある場合のみ判定 |
| 他ホストからの静かなアクセス | ループバック限定バインド、シャットダウン時のピア検証 |

## 既知の制限

- **computer control は無効。** 実行パスはスタブで未登録です。画面や入力の自動化には依存しないでください。
- **委譲境界の強さはエグゼキューター次第。** パスポリシーを守らない実行器では、worktree と事後 diff が実質的な境界です。
- **`mcp-servers.json` と SQLite のパスは旧位置のまま** です。上表のゾーンは `config.json`、資格情報、記憶、worktree、キャッシュに適用され、すべてのファイルではありません。
