title: 运行时边界
description: 跨越每个边界的究竟是什么，以及每个层被允许做什么。
---

CoreLayer 将界面、桌面外壳、守护进程与外部进程相互隔离，使某一层的故障无法悄悄升级成另一层的问题。

## 边界模型

```text
Webview UI（React）
  ║ Tauri IPC —— 仅限显式注册的命令
  ╚═► Tauri 外壳（Rust）
      ║ HTTP —— 仅限回环
      ╚═► Node.js 守护进程（Hono）
          ║ 进程内模块调用（public-api 模块）
          ╠═► 共享包
          ║ 子进程 / 网络
          ╠═► ACP 执行器进程（Claude Code、Codex、OpenCode）
          ╠═► MCP 服务器（stdio 子进程或 HTTP/SSE）
          ╚═► 数据库（SQLite 文件、Supabase、PostgreSQL）
```

## 跨边界规则

| 边界 | 规则 |
|------|------|
| UI → Tauri | 仅限注册命令；不直接访问文件系统或网络 |
| Tauri → 守护进程 | 回环 HTTP；端口在启动时确定并由 `/api/runtime/status` 上报 |
| 守护进程 → 包 | 经各运行时 `public-api.ts` 导入，禁止直接进入内部模块 |
| 守护进程 → 执行器 | 在 git worktree 中的子进程，绑定模型/执行器并受收窄后的边界约束 |
| 守护进程 → MCP 服务器 | stdio 子进程或远程 HTTP/SSE；上报的每个工具都注册并标注风险 |
| 守护进程 → 数据库 | 只经仓储层；路由不直接查询数据库 |

其中一条由机器强制：若某个 HTTP 路由绕过 `public-api.ts` 直接访问运行时内部，导入边界测试会让构建失败。

## UI ↔ Tauri

- 两端都有类型（TypeScript ↔ Rust 结构体）
- 载荷为 JSON
- 调用异步；界面不会阻塞等待守护进程启动

## Tauri ↔ 守护进程

- HTTP，仅限回环。`/api/runtime/shutdown` 还会拒绝非回环对端。
- 流式对话与运行进度使用 SSE。
- 外壳掌管守护进程生命周期：启动、健康检查、崩溃重启、退出时终止。

## 守护进程 ↔ 执行器

编码工作不在守护进程内执行。coding 运行时通过适配器（见 [编码执行器适配器](/docs/guides/coding-executors)）在隔离的 git worktree 中启动外部 Agent，只回读结构化事件、产物与 diff。子进程能做什么在派发时就由[委派边界](/docs/architecture/executor-governance#delegation-bounds)固定，子进程无法自行放宽。

## 为什么重要

- **隔离** — 行为异常的执行器只能破坏自己的工作区
- **可归因** — 每次状态变化都有 run id、操作者与审计记录
- **可替换** — 供应商、执行器或存储后端可独立替换
- **可测试** — 边界由测试强制，而不只靠约定
