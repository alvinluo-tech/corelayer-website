---
title: ランタイム境界
description: 各境界を越えるものは何か、そして各層が何を許されているか。
---

CoreLayer は UI、デスクトップシェル、デーモン、外部プロセスを分離し、ある層の障害が別の層へ静かに波及しないようにします。

## 境界モデル

```text
Webview UI（React）
  ║ Tauri IPC — 明示的に登録されたコマンドのみ
  ╚═► Tauri シェル（Rust）
      ║ HTTP — ループバックのみ
      ╚═► Node.js デーモン（Hono）
          ║ プロセス内モジュール呼び出し（public-api モジュール）
          ╠═► 共有パッケージ
          ║ サブプロセス / ネットワーク
          ╠═► ACP エグゼキュータープロセス（Claude Code、Codex、OpenCode）
          ╠═► MCP サーバー（stdio 子プロセスまたは HTTP/SSE）
          ╚═► データベース（SQLite ファイル、Supabase、PostgreSQL）
```

## 境界を越えるルール

| 境界 | ルール |
|------|--------|
| UI → Tauri | 登録済みコマンドのみ。ファイルシステムやネットワークへの直接アクセスなし |
| Tauri → デーモン | ループバック HTTP。ポートは起動時に決まり `/api/runtime/status` で報告される |
| デーモン → パッケージ | 各ランタイムの `public-api.ts` 経由。内部モジュールへの直接アクセスは禁止 |
| デーモン → エグゼキューター | git worktree 内の子プロセス。モデル/エグゼキューターを固定し、狭められた境界の下で動く |
| デーモン → MCP サーバー | stdio 子プロセスまたはリモート HTTP/SSE。報告された各ツールはリスク付きで登録 |
| デーモン → データベース | リポジトリ層のみ。ルートが直接クエリしない |

そのうち 1 つは機械的に強制されます。HTTP ルートが `public-api.ts` を迂回してランタイム内部へ入ると、インポート境界テストがビルドを失敗させます。

## UI ↔ Tauri

- 両側で型付け（TypeScript ↔ Rust 構造体）
- ペイロードは JSON
- 呼び出しは非同期。UI はデーモン起動を待ってブロックしない

## Tauri ↔ デーモン

- HTTP、ループバックのみ。`/api/runtime/shutdown` は非ループバックのピアを拒否します。
- ストリーミング会話と実行進捗には SSE。
- シェルがデーモンのライフサイクルを所有します：起動、ヘルスチェック、クラッシュ時の再起動、終了時の停止。

## デーモン ↔ エグゼキューター

コーディング作業はデーモン内では実行されません。coding ランタイムはアダプター（[コーディングエグゼキューターアダプター](/docs/guides/coding-executors) 参照）を通じて、隔離された git worktree 内で外部エージェントを起動し、構造化イベント・成果物・diff のみを読み戻します。子プロセスに何が許されるかはディスパッチ時に[委譲の境界](/docs/architecture/executor-governance#delegation-bounds)で固定され、子プロセスが広げることはできません。

## なぜ重要か

- **封じ込め** — 不具合のあるエグゼキューターは自身の worktree しか壊せない
- **帰属** — すべての状態変化に run id、実行者、監査エントリがある
- **置換可能性** — プロバイダー、エグゼキューター、ストレージを独立に差し替えられる
- **テスト可能性** — 境界は規約ではなくテストで強制される
