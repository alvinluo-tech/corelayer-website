---
title: エグゼキューターガバナンス
description: CoreLayer が管理外のコーディングエージェントを監督下のエグゼキューターに変える方法。
---

Claude Code、Codex、OpenCode は強力ですが、シェルに直接向けて動かすと無制限のプロセスになります。どこにでも書き、何でも実行し、何でも報告できます。CoreLayer はそれらを作り直しません。ガバナンス層で包み、「この作業を受け入れてよいか」を決める部分を保持します。

## パイプライン

```text
ディスパッチ要求
  → 委譲境界を検証（プロセスが存在する前に拒否）
  → キュー・スロットを確保
  → 隔離された git worktree を作成
  → 機能プローブ（acpx <agent> sessions ensure）
      ready        → 続行
      needs_auth   → 不足しているログインを伝える
      unreachable  → 起動エラーを報告し、空回りしない
  → エグゼキューターとモデルを固定して起動
  → 子プロセスのイベントを実行イベントへマップ
  → diff と成果物を取得
  → 品質ゲート → 敵対的ジャッジ（有効時）
  → 完了ポリシー：納品、再試行、または理由付き失敗
```

## 委譲の境界

子実行に作業を委譲する実行は、自分ができたことを**狭める**ことしかできません：

| 境界 | 狭め方 |
|------|--------|
| `allowedPaths` | 親の範囲との glob 積集合。リポジトリ外の要求は即座に拒否 |
| `testCommands` | 加算のみ — 親が要求するチェックを子は捨てられない |
| `requiredArtifactTypes` | 加算のみ |
| `timeoutMs` | `min(子, 親, 30 分)`、下限 30 秒 |
| `allowedTools` | 積集合 — 子はより少ないツールしか持てず、親にないツールは持てない |
| `executor` / `executorModel` | 固定。子は別の実行器やモデルに切り替えられない |

特筆すべき 2 つの帰結：親のパス範囲が空なら「まだ制限されていない」ので子の要求が最初の制限になります。また 8,000 文字を超える委譲プロンプトは拒否されます — 委譲は 1 つの仕事を指名するもので、文書の転送ではありません。

## 分離

- 各コーディング実行は `worktrees/active` に独自の git worktree を持ち、保管スナップショットは `worktrees/snapshots` へ。
- パスポリシーは正規化後に判定するため、Windows の区切り文字や `git status` の接頭辞で正当なパスが逸脱に見えることはありません。
- 納品物はレビュー可能なブランチであり、作業ツリーへの直接書き込みではありません。

## 主張ではなく証拠

エグゼキューターが「完了」と言っても証拠にはなりません。CoreLayer は完了を検証可能な主張として扱います：

- **完了ポリシー** — タスクの `test: <command>`、`artifact: <type>`、`path: <glob>` をチェックにコンパイル。自由記述の条件は手動項目として残し、検証済みのふりをしません。
- **品質ゲート** — 必須のゲートが通らない限り納品しません。
- **敵対的ジャッジ** — diff とタスク目標に対する独立レビュー。既定は無効（`adjudication.enabled = false`）。試行ごとにモデル呼び出し 1 回を消費し、diff がありテストコマンドが実際に走ったときだけ証拠を持てます。

## 能力の交渉

実行器がある機能をサポートしているとは仮定しません。能力プローブは ACP ハンドシェイク（`initialize` + `session/new`）を完全に行い、プロンプトターンは送らないためトークンを消費せず、起動構成ごとに結果をキャッシュします。「インストール済み」は、就緒・ログイン不足・起動コマンドの破損を区別できません。

## 意図的にしないこと

- ハングした実行器を無限に再試行しない：実行予算は両側で適用され、環境障害はエージェントのせいにせず分類されます。
- 静かな拡大をしない：付与されていないモデルやパスを子が要求した場合、開始前に拒否します。
- computer control を主張しない：そのランタイムは登録されていません。
