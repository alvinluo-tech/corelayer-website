本页追踪三条关键流程：一次对话轮次、轮次中的一次工具调用，以及被派发后独立于对话继续运行的 Run。

## 对话轮次

```text
1. 用户在聊天面板发送消息
2. 前端 → Tauri IPC → 守护进程 HTTP
     POST /api/conversations/:id/messages/stream   （或 POST /api/chat/stream）
3. agent 运行时组装上下文：
     - 会话历史（按会话、支持分支）
     - 从 memory 运行时检索的长期记忆
     - 核心工具集，以及路由按需选出的工具
4. 模型网关解析当前供应商/模型并发起流式调用
     （Vercel AI SDK v6；步进控制在 prepareStep 内完成）
5. 每个步骤可以：
     - 输出文本 → 流式送达界面
     - 请求工具调用 → 进入下方的工具调用流程
6. 熔断器与步数预算决定本轮继续还是停止
7. 完成策略与质量门禁决定结果是否可交付
8. 最终消息持久化，SSE 流关闭
```

## 工具调用

```text
模型请求工具调用
  → 工具注册中心解析工具（native / MCP / skill）
  → 权限守卫读取工具上声明的风险（不靠推断）
  → 策略判定：
      auto    → 直接执行
      notify  → 执行并提示
      confirm → 创建审批请求，挂起运行，等待决定后恢复
      deny    → 阻止并记录
  → 执行
  → 写入审计（操作者、动作、风险、决定、结果）
  → 将结果返回模型
```

审批是持久化的，而非只存在于内存中：待决定请求在守护进程重启后仍然存在，用户做出决定后由恢复服务继续。

## 派发的运行

```text
用户目标 / 委派任务
  → run dispatcher 校验边界（委派只能收窄）
  → 队列条目占用槽位（并发按资源类别设上限）
  → coding 运行时创建 git worktree
  → 执行器适配器启动子 Agent（ACP）
  → 能力探测：ready / needs_auth / unreachable
  → 子进程流式输出事件 → 事件映射 → 事件日志
  → diff 与产物写入 run 记录
  → 质量门禁 / 对抗式仲裁（若启用）
  → 完成策略：通过 → 交付分支；失败 → 带原因失败
```

每次状态迁移都会写入 `agent_run` 事件，因此 `GET /api/runs/:id/events` 可以在事后重建一次运行，也正因如此运行可以按 id 取消或重试。

## MCP 连接

```text
1. 守护进程从 mcp-servers.json 读取服务器定义
2. 启动子进程（stdio）或通过 HTTP/SSE 连接
3. 完成 MCP initialize 握手
4. 读取工具列表，按服务器风险策略逐个注册
5. 工具对路由与模型可用
6. 断连后标记为 disconnected，可重启
```

## 存储写入

```text
路由或运行时 → 仓储层（SQLite / Supabase / PostgreSQL）
  → schema 校验
  → 写入
  → （若为事件）同时追加到事件日志
```

存储模式在启动时从 `storage.json` 读取（`local`、`cloud`、`postgres`）。详见 [存储](/docs/configuration/storage)。

## 语音轮次

```text
唤醒词 → 打开麦克风 → ASR 流式输出临时与最终转写
  → 最终转写与键盘输入走完全相同的对话管线
  → 回复流式返回；TTS 按句播报
  → 打断：播放中说话会中断音频并回到 ASR
```
