CoreLayer はローカルファーストのデスクトップ **Agent OS** です。Tauri シェルが UI を載せ、Node.js デーモンを監督します。デーモンがすべてのランタイム、すべてのツール呼び出し、すべての永続化状態を所有します。

本ページは**現在実際に動いているシステム**を説明します。長期的な方向性は [マルチランタイムの方向性](/docs/architecture/multi-runtime-direction) を参照してください。

## トポロジー

```text
┌──────────────────────────────────────────────────────────────┐
│ Tauri デスクトップシェル（Rust）                              │
│   ├─ Webview UI（React 19 + Vite + Tailwind）                │
│   ├─ デーモン監督：起動 / ヘルスチェック / 再起動 / 停止       │
│   └─ HTTP プロキシ → ローカルデーモン                         │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTP（ループバックのみ、既定 3001）
┌───────────────────────────┴──────────────────────────────────┐
│ Node.js デーモン（TypeScript + Hono）                         │
│                                                              │
│  ランタイムホスト（登録 · ライフサイクル · ステータス）        │
│   ├─ agent        — 会話ループとツール呼び出し                │
│   ├─ tool         — レジストリ、ルーティング、ネイティブツール │
│   ├─ coding       — エグゼキューターアダプター、worktree、ゲート│
│   ├─ memory       — 長期記憶とスナップショット                 │
│   ├─ voice        — ウェイクワード、ASR、TTS、バージイン       │
│   └─ scheduler    — cron による自律作業                       │
│                                                              │
│  ワークフロー面                                               │
│   ├─ run dispatcher / queue / slot manager                   │
│   ├─ delegation（単調な狭小化）                               │
│   ├─ task graph DAG エグゼキューター                          │
│   └─ adjudication（敵対的ジャッジ）                           │
│                                                              │
│  横断的機能                                                   │
│   ├─ パーミッションガード + 承認（HITL）                      │
│   ├─ 監査ログ + イベントログ                                  │
│   └─ 永続化（既定 SQLite；Supabase / PostgreSQL は任意）      │
└──────────────────────────────────────────────────────────────┘
```

## レイヤーの責務

### フロントエンド（React）

会話、ワークスペース、実行、承認、設定を描画します。デーモンへは Tauri ブリッジ経由でのみ接続し、データベースやプロバイダーへ直接接続しません。

### Tauri ブリッジ（Rust）

デーモン sidecar の起動と監督、HTTP の転送、ネイティブ機能（パス、ウィンドウ、トレイ）を提供します。IPC コマンドはすべて明示的に登録されます。

### デーモン（Node.js）

権限を持つ唯一のコンポーネントです。ランタイムレジストリを保持し、コンテキストを組み立て、モデルゲートウェイ経由でモデルを呼び、パーミッションガードの後ろでツールを実行し、リポジトリ層を通して永続化します。

### 共有パッケージ

デーモンはロジックを複製せず、8 つのワークスペースパッケージを組み合わせます：

| パッケージ | 役割 |
|-----------|------|
| `@jarvis/types` | 共有 TypeScript 型 |
| `@jarvis/model-gateway` | プロバイダー解決とモデルルーティング |
| `@jarvis/mcp-client` | MCP 接続（stdio、HTTP、SSE） |
| `@jarvis/tool-registry` | ツールカタログと解決 |
| `@jarvis/permission-guard` | リスク分類、ポリシー、監査 |
| `@jarvis/runtime-core` | ランタイムのライフサイクル基盤 |
| `@jarvis/runtime-protocol` | ランタイム契約の定義 |
| `@jarvis/execution-environment` | 実行抽象（worktree ベース） |

## 登録されているランタイム

登録コードは `daemon/src/runtimes/index.ts` にあります。ランタイムホストに登録され、`GET /api/runtime/components` で状態を報告するのは 6 つです：

`agent`、`tool`、`coding`、`memory`、`voice`、`scheduler`。

**computer-control は登録されていません。** リスク・権限・監査の層とツール定義は存在しますが、実行パスは OS に触れずに成功を返すままで、Rust 側の機能もありません。登録すると「動いているのに何もしない」ランタイムを公開することになるため、実装が入るまでホストから外しています。これを有効なランタイムとして挙げる文書（本ファイルの過去版を含む）は誤りです。

## 通信

```text
ユーザー入力
  → React フロントエンド
  → Tauri IPC
  → Rust デーモン監督（HTTP プロキシ）
  → Hono ルート（/api/conversations/:id/messages/stream、/api/chat/stream など）
  → agent ランタイム：コンテキスト組み立て → モデル → ツール呼び出し → 完了ポリシー
  → 同じ経路で SSE / JSON を返す
```

長時間の作業は会話ターンをブロックしません。run dispatcher が `agent_run` を永続化し、キューがスロットを占有し、進捗はイベントログに書き込まれます。クライアントは `GET /api/events` と `GET /api/runs/:id/events` で読み取ります。
