---
title: 执行器治理
description: CoreLayer 如何把“裸跑”的编码 Agent 变成受监管的执行器。
---

Claude Code、Codex、OpenCode 能力很强，但直接对着 shell 运行就是一个无界进程：能写任何位置、执行任何命令、汇报任何结论。CoreLayer 不重写它们，而是在外面包一层治理，并保留“这次工作是否可接受”的判断权。

## 流水线

```text
派发请求
  → 校验委派边界（在任何进程创建前就拒绝）
  → 分配队列槽位
  → 创建隔离的 git worktree
  → 能力探测（acpx <agent> sessions ensure）
      ready        → 继续
      needs_auth   → 告知用户缺少哪个登录
      unreachable  → 报告启动错误，不空转
  → 绑定执行器与模型后启动
  → 将子进程事件流映射为运行事件
  → 捕获 diff 与产物
  → 质量门禁 → 对抗式仲裁（若启用）
  → 完成策略：交付、重试，或带原因失败
```

## 委派边界

一次将工作委派给子运行的运行，只能**收窄**自己本来能做的事：

| 边界 | 收窄规则 |
|------|----------|
| `allowedPaths` | 与父级范围做 glob 交集；越出仓库的请求直接拒绝 |
| `testCommands` | 只增不减——子运行不能丢掉父级要求的检查 |
| `requiredArtifactTypes` | 只增不减 |
| `timeoutMs` | `min(子, 父, 30 分钟)`，下限 30 秒 |
| `allowedTools` | 取交集——子运行工具只能更少，不能持有父级没有的工具 |
| `executor` / `executorModel` | 绑定；子运行不能更换执行器或模型 |

两个需要说明的后果：父级路径范围为空意味着“尚未受限”，此时子请求成为第一道约束；委派提示词超过 8000 字符会被拒绝——委派是交代一件事，不是传文档。

## 隔离

- 每次编码运行在 `worktrees/active` 下拥有独立 git worktree，归档快照写入 `worktrees/snapshots`。
- 路径策略在规范化之后再判定所收到的路径，因此 Windows 分隔符与 `git status` 前缀无法让合法路径看起来像越界。
- 交付物是可审查的分支，而不是对你工作区的直接写入。

## 证据而非声明

执行器说“完成了”不构成证据。CoreLayer 把完成当作可检验的声明：

- **完成策略** — 任务中的 `test: <命令>`、`artifact: <类型>`、`path: <glob>` 会被编译成检查项；自由文本条件保留为人工项，不会假装已验证。
- **质量门禁** — 某类任务的必需门禁未通过时不予交付。
- **对抗式仲裁** — 由独立评审针对 diff 与任务目标判定，默认关闭（`adjudication.enabled = false`）。每次尝试消耗一次模型调用，且只有在存在 diff 并真的执行过测试命令时才有证据可判。

## 能力协商

系统不假设执行器支持某项能力。能力探测会完成完整的 ACP 握手（`initialize` + `session/new`）但不发送提示轮次，因此不消耗 token，并按启动配置缓存结果。这个区分很重要：“已安装”无法告诉你 Agent 是就绪、缺登录，还是启动命令坏了。

## 刻意不做的事

- 不对卡死的执行器无限重试：运行预算在两侧各生效一次，环境故障会被分类，而不是归咎于 Agent。
- 不静默放宽：子运行若请求未获授权的模型或路径，会在启动前被拒绝。
- 不谎称支持 computer control：该运行时未注册。
