Jarvis は内蔵のアシスタントペルソナです。独立したサービスではなく、agent ランタイムの会話ループに、システムプロンプト・ツール・ガバナンスを添えたものです。作業を調整しますが、そのために権限システムを迂回することはありません。

## 1 ターンの流れ

```text
入力（テキストまたは音声の文字起こし）
  → コンテキストの組み立て
      会話履歴（ブランチ対応）
      長期記憶（MEMORY.md / USER.md のスナップショット + 取得した記憶）
      コアツール + ルーターが選ぶオンデマンドツール
  → モデルゲートウェイが有効なプロバイダーとモデルを解決
  → Vercel AI SDK v6 ループ。ステップ制御は prepareStep 内
  → ツール呼び出しはパーミッションガードを通る
  → ループブレーカー、ステップ予算、ターンタイムアウトがターンを制約
  → 完了ポリシーと品質ゲートが納品可否を決める
```

## できること

| 能力 | 補足 |
|------|------|
| 会話とツール呼び出し | ネイティブツール、MCP ツール、動的発見ツール |
| 長時間作業 | 実行をディスパッチ。会話ターンを越えて存続し、id でキャンセル可能 |
| コーディング委譲 | worktree 内の管理された外部エグゼキューターへ委譲 |
| タスクグラフ | 宣言的 DAG。独立ノードは並行実行 |
| 記憶 | 永続的な長期記憶 + ターンごとに注入する凍結スナップショット |
| 音声 | ウェイクワード、ストリーミング ASR、文単位 TTS、バージイン |
| スケジュール | cron による自律実行 |

## 記憶

記憶は単一のチャット履歴ではなく階層化されています：

- **明示的な Markdown 記憶** — 記憶ゾーンの `USER.md` と `MEMORY.md`。あなたが直接読み書きできる
- **取得された記憶** — 保存エントリを現在のターンで採点し、設定可能な下限（`defaults.memoryMinScore`）を超えたものだけ注入
- **凍結スナップショット** — 注入される記憶は実行ごとにスナップショット化され、開始後に書かれた記憶はそのターンには見えない
- **注入トラッキング** — 各記憶が最後に注入された時刻を記録し、高頻度の項目が無限に再注入されないようにする

## 委譲

Jarvis は子実行へタスクを渡せますが、境界は狭めるだけです：パスは積集合、ツールは積集合、必須チェックは加算のみ、実行器とモデルは固定。詳細は [エグゼキューターガバナンス](/docs/architecture/executor-governance) を参照。

## 誠実性の制約

- Jarvis はツール出力を命令ではなくデータとして扱うよう指示されます。
- 設定された証拠（テスト、成果物、範囲）が成立したときだけ完了を納品します。
- 敵対的ジャッジが有効で diff が拒否された場合、`adjudication.maxRetries` の範囲で再試行し、その後は成功と報告せず失敗します。
