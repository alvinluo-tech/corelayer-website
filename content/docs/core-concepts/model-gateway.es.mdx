---
title: Model Gateway
description: Como CoreLayer convierte un id de proveedor en una llamada de modelo en streaming.
---

El Model Gateway es el unico camino de un turno de agente hacia un modelo. Resuelve el proveedor activo, adapta la peticion a la familia de modelo, hace streaming y degrada cuando un proveedor no esta sano.

## Camino

```text
Turno del agente
  → activeProvider / activeModel (o coincidencia de una regla de enrutado)
  → resolveProvider(id): configuracion → credenciales → entorno → base URL por defecto
  → cliente compatible con OpenAI (Vercel AI SDK v6)
  → adaptacion por familia (modelos de razonamiento, Anthropic)
  → llamada en streaming
  → deltas de texto y tool calls de vuelta al bucle
```

## Un adaptador, muchos proveedores

Todos los proveedores remotos se llaman por el mismo adaptador compatible con OpenAI. Eso es lo que hace a los proveedores intercambiables: un proveedor es una base URL y una clave, y su lista de modelos es dato en lugar de una rama de codigo.

## Control del bucle

El bucle del agente es el bucle core de Vercel AI SDK, no un `while` escrito a mano:

- `prepareStep` decide por paso que herramientas existen y si el turno puede continuar
- los loop breakers (llamadas identicas repetidas, deteccion de falta de progreso) y el presupuesto de pasos (`defaults.maxSteps`, maximo 100) acotan el turno
- timeouts: `streamTimeout` por llamada, `turnTimeout` por turno

La inyeccion de mensajes a mitad de ejecucion en un bucle escrito a mano ya no existe; `POST /api/runs/:id/message` devuelve `410`.

## Streaming

Las respuestas se hacen streaming por defecto:

- El texto aparece segun se genera
- TTS puede leer oracion por oracion
- Las tool calls se ejecutan en cuanto un paso las produce

## Salud y fallback

Un proveedor que falla dos veces seguidas entra en un cooldown de 20 segundos con backoff exponencial en fallos repetidos. Mientras esta en cooldown, las llamadas lo saltan en lugar de esperar el mismo timeout. El primer exito resetea el contador.

## Medir coste

El uso de tokens se registra cuando el proveedor lo reporta. Los ejecutores manejados por ACP no se pueden medir (el protocolo no tiene actualizacion de uso), asi que sus cifras de coste son explicitamente estimaciones y no recuentos del proveedor.
