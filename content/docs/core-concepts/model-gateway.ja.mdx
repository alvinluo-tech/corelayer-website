---
title: モデルゲートウェイ
description: CoreLayer がプロバイダー id をストリーミングモデル呼び出しに変える方法。
---

モデルゲートウェイは、エージェントターンからモデルへの唯一の経路です。有効なプロバイダーを解決し、モデルファミリーに合わせて要求を調整し、ストリーミングし、プロバイダーが不健全なときは縮退します。

## 経路

```text
エージェントターン
  → activeProvider / activeModel（またはルーティング規則の一致）
  → resolveProvider(id)：設定 → 資格情報 → 環境変数 → 既定 base URL
  → OpenAI 互換クライアント（Vercel AI SDK v6）
  → モデルファミリー適応（推論モデル、Anthropic）
  → ストリーミング呼び出し
  → テキスト差分とツール呼び出しがループへ戻る
```

## 1 つのアダプター、多数のプロバイダー

すべてのリモートプロバイダーは同じ OpenAI 互換アダプターを通ります。だからプロバイダーは差し替え可能です。プロバイダーは base URL とキーであり、モデル一覧はコード分岐ではなくデータです。

## ループ制御

エージェントループは Vercel AI SDK のコアループであり、手書きの `while` ではありません：

- `prepareStep` がステップごとに利用可能ツールと継続可否を決める
- ループブレーカー（同一呼び出しの繰り返し、進展なし検出）とステップ予算（`defaults.maxSteps`、上限 100）がターンを制約
- タイムアウト：呼び出しごと `streamTimeout`、ターンごと `turnTimeout`

手書きループへの中途メッセージ注入は廃止されました。`POST /api/runs/:id/message` は `410` を返します。

## ストリーミング

応答は既定でストリーミングされます：

- テキストは生成とともに現れる
- TTS は文単位で読み上げ可能
- ツール呼び出しはステップが返した時点で実行

## 健康と縮退

2 回連続で失敗したプロバイダーは 20 秒のクールダウンに入り、繰り返し失敗すると指数バックオフします。クールダウン中は同じタイムアウトを待たずにスキップします。1 回成功すればリセットされます。

## コスト計測

トークンはプロバイダーが用量を報告したときに記録されます。ACP 経由のエグゼキューターは計量できません（プロトコルに用量更新がない）ため、これらの実行のコストは集計値ではなく明示的な推定値です。
