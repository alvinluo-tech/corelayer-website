---
title: 記憶
description: CoreLayer が Jarvis の記憶をどこに保存し、ターン内の書き込みがなぜターンを汚さないのか。
---

CoreLayer の記憶は明示的です。隠れた状態はなく、モデルが覚えているのはディスクやデータベースに書かれた内容であり、その最も重要な部分は手で読み書きできます。

## レイヤー

| レイヤー | 場所 | 内容 |
|---------|------|------|
| **プロフィール** | `memory/USER.md` | あなたが誰か、硬い制約 |
| **長期的事実** | `memory/MEMORY.md` | 永続する事実と嗜好 |
| **構造化記憶** | `memories` テーブル | キー付き `fact` / `preference` / `context`。検索・採点可能 |
| **ジャーナル** | `memory/journal/` | 日次追記用に予約されたディレクトリ（起動時に作成。書き込み実装は未提供） |
| **リフレクション** | `memory/dreams/` | リフレクション出力用に予約（起動時に作成。リフレクションループは既定オフ） |

## 凍結スナップショット

ターン開始時に `USER.md` と `MEMORY.md` を不変スナップショットとして読み込み、プロンプト接頭辞に置きます。ターン内の書き込み（エージェントの事実保存、あなたのファイル編集）はディスクと記憶インデックスを即座に更新しますが、**そのターンで有効な接頭辞は変更しません**。

これは正しさのルールであると同時にコストのルールです：ターン内で変化する接頭辞はプロバイダーのプロンプトキャッシュを毎ステップ無効化します。接頭辞を凍結すればキャッシュが効き、ターンのコンテキストも再現可能になります。

## 取得

構造化記憶はスコアで取得され、下限（`defaults.memoryMinScore`、既定 `0.3`）があります。下限未満は注入されません。弱い一致の注入はコンテキストを浪費し、モデルの注意を散らします。

注入は追跡されます：各記憶は最後に注入された時刻を記録し、高頻度の項目がターンごとに他を圧迫しないようにします。

## 記憶の書き込み

| ツール | リスク | 補足 |
|--------|--------|------|
| `memory_store` | `medium` | 保存した記憶は以後のすべての提示に再注入される。不活性な記録ではなく持続的な影響 |
| `memory_search` / `memory_list` | `low` | 読み取り経路 |
| `memory_delete` | `high` | 破壊的。確認が必要 |

`memory_store` を `medium` にするのは意図的です。汚染されたエントリは作成した会話より長く生き残ります。

## キーによるアドレス指定

記憶は `key`（短く安定。例：`coding_style`）で扱います。同じキーへの再保存は重複を作らず更新するため、`memory_store` は実行をまたいで冪等です。
