---
title: El Daemon
description: El proceso Node.js que posee todos los runtimes, llamadas a herramientas y estado.
---

El daemon es un proceso de Node.js (TypeScript, HTTP con Hono) que corre en segundo plano y tiene toda la autoridad. El shell de Tauri lo supervisa; ningun otro componente habla directamente con un proveedor, una base de datos o un ejecutor.

## Anatomia

```text
Shell de escritorio Tauri (Rust)
  └─ Supervisor del daemon (arranque · salud · reinicio · terminacion)
     └─ Daemon Node.js (Hono, HTTP en loopback)
        ├─ Host de runtimes     agent · tool · coding · memory · voice · scheduler
        ├─ Plano de workflow    dispatcher · queue · slots · delegation · DAG · judge
        ├─ Permission Guard     riesgo → politica → aprobacion → auditoria
        ├─ Cliente MCP          servidores stdio / HTTP / SSE
        └─ Persistencia         SQLite (por defecto) · Supabase · PostgreSQL
```

## Proceso supervisor

El lado Rust:

- arranca el sidecar del daemon al iniciar la app
- comprueba salud y reinicia tras una caida
- pasa rutas y puertos por variables de entorno
- termina el daemon al salir

El estado de los runtimes llega a la UI por `GET /api/runtime/status` (pid, uptime, memoria, modo de almacenamiento, rutas, salud por runtime) y `GET /api/runtime/components`.

## Superficie HTTP

El daemon escucha en loopback, puerto `3001` por defecto. Los grupos de rutas se montan en `daemon/src/bootstrap/register-routes.ts`:

`/api/chat` · `/api/conversations` · `/api/tasks` · `/api/articles` · `/api/reviews` · `/api/settings` · `/api/voice` · `/api/mcp` · `/api/tools` · `/api/tasks/scheduled` · `/api/approvals` · `/api/workspaces` · `/api/projects` · `/api/runs` · `/api/runtimes` · `/api/runtime/queue` · `/api/memories` · `/api/agent-profiles` · `/api/events` · `/api/audit` · `/api/runtime` · `/api/agent-broker`

Ver [Endpoints API](/docs/reference/api-endpoints) para los importantes.

## Desarrollo y produccion

| Modo | Como corre |
|------|------------|
| Desarrollo | `pnpm dev:daemon` — `tsx watch` reinicia al cambiar |
| Produccion | `pnpm build:daemon:sidecar` — binario SEA lanzado por el shell |

## Estado

El daemon no tiene estado entre reinicios salvo lo que persiste. El trabajo de larga duracion se guarda como ejecuciones y entradas de cola, y las aprobaciones pendientes se almacenan, asi un reinicio reanuda en lugar de olvidar.
