---
title: 守护进程
description: 拥有全部运行时、工具调用与状态的 Node.js 进程。
---

守护进程是一个在后台运行的 Node.js 进程（TypeScript + Hono HTTP），拥有全部权限。Tauri 外壳监管它；除此之外任何组件都不得直连模型供应商、数据库或执行器。

## 结构

```text
Tauri 桌面外壳（Rust）
  └─ 守护进程监管（启动 · 健康 · 重启 · 终止）
     └─ Node.js 守护进程（Hono，回环 HTTP）
        ├─ 运行时宿主        agent · tool · coding · memory · voice · scheduler
        ├─ 工作流平面        dispatcher · queue · slots · delegation · DAG · judge
        ├─ 权限守卫          风险 → 策略 → 审批 → 审计
        ├─ MCP 客户端        stdio / HTTP / SSE 服务器
        └─ 持久化            SQLite（默认）· Supabase · PostgreSQL
```

## 监管进程

Rust 侧负责：

- 应用启动时拉起守护进程 sidecar
- 健康检查并在崩溃时重启
- 通过环境变量传入路径与端口
- 退出时终止守护进程

运行状态通过 `GET /api/runtime/status`（pid、运行时长、内存、存储模式、路径、各运行时健康）与 `GET /api/runtime/components` 暴露给界面。

## HTTP 接口

守护进程监听回环，默认端口 `3001`。路由分组在 `daemon/src/bootstrap/register-routes.ts` 中挂载：

`/api/chat` · `/api/conversations` · `/api/tasks` · `/api/articles` · `/api/reviews` · `/api/settings` · `/api/voice` · `/api/mcp` · `/api/tools` · `/api/tasks/scheduled` · `/api/approvals` · `/api/workspaces` · `/api/projects` · `/api/runs` · `/api/runtimes` · `/api/runtime/queue` · `/api/memories` · `/api/agent-profiles` · `/api/events` · `/api/audit` · `/api/runtime` · `/api/agent-broker`

重要端点见 [API 参考](/docs/reference/api-endpoints)。

## 开发与生产

| 模式 | 运行方式 |
|------|----------|
| 开发 | `pnpm dev:daemon` — `tsx watch` 变更即重启 |
| 生产 | `pnpm build:daemon:sidecar` — 打包为 SEA 二进制，由外壳拉起 |

## 状态

除持久化的内容外，守护进程在重启之间是无状态的。长任务以运行记录与队列条目持久化，待定审批也会落库，因此重启是“续上”而不是“遗忘”。
