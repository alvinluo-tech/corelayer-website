---
title: 技能
description: 需要先挣得“无人值守运行权”的程序性知识。
---

技能是以 `SKILL.md` 形式保存的程序性知识：如何把项目改造成 MCP 服务器、团队如何做评审、仓库如何发布。技能按需加载进上下文，而不是常驻。

## 信任是挣来的

积累技能不等于变强。一个技能可能来自一次侥幸成功的运行，可能不适用于当前仓库，也可能已经开始失败。因此 CoreLayer 在技能无人值守运行前会评估：

```text
请求使用技能
  → evaluateSkillTrust(manifest)
      已弃用？                 → 仅建议
      autonomy: "suggest"？    → 仅建议
      连续 3 次失败？          → 降级为仅建议
      从未成功过？             → 仅建议
      其余                     → 可自动运行
```

“仅建议”并不会禁用技能。它仍然可用，只是必须被显式请求。

## 执行历史

每次执行都会把结果（`success`、`error`、`runId`、`executedAt`）追加到技能的 provenance，最多保留 20 条。信任规则读取的就是这段历史，因此一个开始失败的技能会自行失去自主权，无需人工编辑。

## 格式

```text
skills/
└── my-skill/
    └── SKILL.md
```

```markdown
# 我的技能

一句话说明这个技能做什么。

## 何时使用

适用条件。

## 步骤

### 步骤 1：收集上下文
### 步骤 2：执行
### 步骤 3：验证并汇报
```

## 内建技能

| 技能 | 用途 |
|------|------|
| `corelayer-mcp-adapter` | 指导把任意项目改造成 CoreLayer 兼容的 MCP 服务器 |

## 编写建议

- 写清适用条件，而不只是步骤。
- 包含验证步骤；没有可检验结果的技能无法挣得信任。
- 优先使用确定性步骤（命令、文件），少用散文式指令。
- 若需要提权，明确说明，而不是笼统索取宽权限。
