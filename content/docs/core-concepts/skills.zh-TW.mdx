---
title: 技能
description: 需要先掙得「無人值守執行權」的程序性知識。
---

技能是以 `SKILL.md` 形式保存的程序性知識：如何把專案改造成 MCP 伺服器、團隊如何做審查、儲存庫如何發佈。技能按需載入進上下文，而不是常駐。

## 信任是掙來的

累積技能不等於變強。一個技能可能來自一次僥倖成功的執行，可能不適用於目前儲存庫，也可能已經開始失敗。因此 CoreLayer 在技能無人值守執行前會評估：

```text
請求使用技能
  → evaluateSkillTrust(manifest)
      已棄用？                 → 僅建議
      autonomy: "suggest"？    → 僅建議
      連續 3 次失敗？          → 降級為僅建議
      從未成功過？             → 僅建議
      其餘                     → 可自動執行
```

「僅建議」並不會停用技能。它仍然可用，只是必須被顯式請求。

## 執行歷史

每次執行都會把結果（`success`、`error`、`runId`、`executedAt`）追加到技能的 provenance，最多保留 20 筆。信任規則讀取的就是這段歷史，因此一個開始失敗的技能會自行失去自主權，無需人工編輯。

## 格式

```text
skills/
└── my-skill/
    └── SKILL.md
```

```markdown
# 我的技能

一句話說明這個技能做什麼。

## 何時使用

適用條件。

## 步驟

### 步驟 1：收集上下文
### 步驟 2：執行
### 步驟 3：驗證並回報
```

## 內建技能

| 技能 | 用途 |
|------|------|
| `corelayer-mcp-adapter` | 指導把任意專案改造成 CoreLayer 相容的 MCP 伺服器 |

## 撰寫建議

- 寫清適用條件，而不只是步驟。
- 包含驗證步驟；沒有可檢驗結果的技能無法掙得信任。
- 優先使用確定性步驟（指令、檔案），少用散文式指令。
- 若需要提權，明確說明，而不是籠統索取寬權限。
