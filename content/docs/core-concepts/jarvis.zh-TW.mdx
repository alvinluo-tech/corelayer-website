Jarvis 是內建的助理人格。它不是一個獨立服務——它是 agent 執行階段的會話迴圈，加上圍繞它的系統提示詞、工具與治理。它協調工作，但不會為了協調而繞過權限系統。

## 一回合如何發生

```text
輸入（文字或語音轉寫）
  → 上下文組裝
      會話歷史（支援分支）
      長期記憶（MEMORY.md / USER.md 快照 + 檢索到的記憶）
      核心工具 + 路由按需選出的工具
  → 模型閘道解析目前供應商與模型
  → Vercel AI SDK v6 迴圈；步進控制在 prepareStep 中
  → 工具呼叫經權限守護
  → 熔斷器、步數預算與回合逾時約束本回合
  → 完成策略與品質閘門決定是否交付
```

## 能做什麼

| 能力 | 說明 |
|------|------|
| 對話與工具呼叫 | 原生工具、MCP 工具與動態發現的工具 |
| 長任務 | 派發執行；它獨立於對話繼續存在，可按 id 取消 |
| 編碼委派 | 交給 worktree 中的受管外部執行器 |
| 任務圖 | 宣告式 DAG，獨立節點併發執行 |
| 記憶 | 持久長期記憶 + 每回合注入的凍結快照 |
| 語音 | 喚醒詞、串流 ASR、句級 TTS、打斷續聽 |
| 排程 | 定時觸發的自治執行 |

## 記憶

記憶是分層的，而不是單一聊天歷史：

- **顯式 Markdown 記憶** — 記憶分區下的 `USER.md` 與 `MEMORY.md`，你可直接讀寫
- **檢索記憶** — 儲存條目按目前回合評分，高於可設定閾值（`defaults.memoryMinScore`）才注入
- **凍結快照** — 注入的記憶在每次執行時被快照固定，因此本回合看不到啟動之後才寫入的記憶
- **注入追蹤** — 記憶會記錄最近一次注入時間，避免高頻條目被無限制反覆注入

## 委派

Jarvis 可以把任務交給子執行，但邊界只會收窄：路徑取交集、工具取交集、必需檢查只增不減、執行器與模型被綁定。詳見 [執行器治理](/docs/architecture/executor-governance)。

## 誠實性約束

- Jarvis 被要求把工具輸出當作資料，而不是指令。
- 只有在設定的證據（測試、產物、範圍）成立時才交付完成。
- 開啟對抗式仲裁且 diff 被拒時，會在 `adjudication.maxRetries` 內重試，之後如實失敗，而不是回報成功。
