工具註冊表是每次工具呼叫的解析入口。它彙整原生工具與 MCP 提供的工具，也是工具風險等級被宣告的地方。

## 來源

| 來源 | 說明 | ID 形式 |
|------|------|---------|
| **原生** | 在 tool 執行階段中實作的工具 | `native:<name>` |
| **MCP** | 已連線 MCP 伺服器上報的工具 | `mcp:<serverId>:<toolName>` |

## 風險靠宣告，而非推斷

每個原生工具註冊時必須顯式給出風險等級：

```ts
registerTool("dispatch_agent", tool({ ... }), "high");
```

這是一條刻意的約束。曾經用工具名推斷風險，結果 `dispatch_agent` 與 `run_task_graph` 因為名字裡沒有危險詞被判為 `low`——而它們都會派生寫入檔案、執行指令的執行，而 `low` 預設自動放行。名字不是效果的證據。

## 核心工具與按需發現

每回合都暴露全部工具 schema 會消耗上下文並降低工具選擇品質。因此路由分兩層：

1. **核心工具** 始終可用。
2. **其餘工具** 透過 `search_tools` 按查詢匹配完整目錄並回傳匹配項的 schema。模型用找到的工具做計畫，而不是背著整個目錄。

## 內建原生工具

| 工具 | 風險 | 用途 |
|------|------|------|
| `get_code_skeleton` | `low` | 檔案或符號的 AST 剪枝骨架——保留簽名與型別，摺疊函式體 |
| `search_tools` | `low` | 發現核心集之外的工具 |
| `listConversations` | `low` | 列出會話 |
| `previewConversationCleanup` | `low` | 清理查詢的試執行 |
| `taskflow_create_task` | `medium` | 建立任務 |
| `taskflow_list_tasks` | `low` | 列出任務 |
| `deleteConversation` | `high` | 刪除單一會話 |
| `deleteConversationsByQuery` | `high` | 按查詢批次刪除 |
| `requestConversationCleanup` | `high` | 經核准的清理 |
| `dispatch_agent` | `high` | 向子 Agent 委派一次受限執行 |
| `run_task_graph` | `high` | 執行編碼子任務 DAG |
| `createTask` / `updateTask` | `medium` | 任務管理 |
| `getTodayTasks` / `queryTasks` | `low` | 查詢任務 |
| `deleteTask` | `high` | 刪除任務 |
| `addArticle` / `updateReadingStatus` | `medium` | 閱讀清單 |
| `getReadingList` / `getReadingStats` / `recommendNext` | `low` | 閱讀查詢 |
| `getDailySummary` / `getWeeklyStats` / `getReviewHistory` | `low` | 回顧查詢 |
| `saveReview` | `medium` | 儲存回顧 |
| `memory_store` | `medium` | 寫入長期記憶（會持續影響後續提示，故非 `low`） |
| `memory_search` / `memory_list` | `low` | 讀取記憶 |
| `memory_delete` | `high` | 刪除記憶 |

所有原生工具都在註冊時宣告風險，不依賴名稱或參數推斷。

MCP 工具攜帶伺服器設定的風險策略（`riskPolicy` 按等級），並在連線時註冊。

## 解析

```text
模型請求工具 "search_tools"
  → 註冊中心解析 native:search_tools
  → 權限守護讀取宣告的風險
  → 策略判定 auto / notify / confirm / deny
  → 執行、稽核、回傳
```

解析同時接受裸名稱與 `native:` 前綴，因此模型無需了解命名空間。

## 查看註冊中心

- `GET /api/tools` — 列出已註冊工具
- `GET /api/tools/:id` — 單一工具
- `POST /api/tools/filter` — 按來源或風險篩選
- `POST /api/tools/:id/execute` — 直接執行（仍經過權限檢查）
- `GET /api/tools/logs` — 最近的呼叫日誌
