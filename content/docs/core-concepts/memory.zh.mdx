---
title: 记忆
description: CoreLayer 如何存储 Jarvis 记住的内容，以及为什么轮内写入不会污染本轮。
---

CoreLayer 的记忆是显式的：没有隐藏状态，模型记住的就是写进磁盘或数据库的内容，其中最重要的部分你可以手写修改。

## 分层

| 层 | 位置 | 内容 |
|----|------|------|
| **用户画像** | `memory/USER.md` | 你是谁，以及硬性约束 |
| **长期事实** | `memory/MEMORY.md` | 持久的事实与偏好 |
| **结构化记忆** | `memories` 表 | 带 key 的 `fact` / `preference` / `context` 条目，可检索、可评分 |
| **日记** | `memory/journal/` | 为按天追加的笔记预留的目录（启动时创建，尚未有写入实现） |
| **反思** | `memory/dreams/` | 为反思输出预留的目录（启动时创建，反思循环默认关闭） |

## 冻结快照

每轮开始时，`USER.md` 与 `MEMORY.md` 被读入一个不可变快照，放入提示词前缀。轮内写入——Agent 保存一条事实，或你编辑文件——会立即更新磁盘与记忆索引，但**不会修改本轮已生效的前缀**。

这同时是正确性规则与成本规则：轮内变化的提示词前缀会让供应商的提示缓存每一步都失效。冻结前缀既保持缓存命中，也让本轮的上下文可复现。

## 检索

结构化记忆按评分检索，并设有下限（`defaults.memoryMinScore`，默认 `0.3`）。低于下限的记忆不会被注入；注入弱匹配既浪费上下文，也会分散模型注意力。

注入会被追踪：每条记忆记录最近一次注入时间，避免某个高频条目在后续每一轮都挤占其他记忆。

## 写入记忆

| 工具 | 风险 | 说明 |
|------|------|------|
| `memory_store` | `medium` | 存储的记忆会被注入后续每一次提示——这是持久影响，不是惰性记录 |
| `memory_search` / `memory_list` | `low` | 读取路径 |
| `memory_delete` | `high` | 破坏性操作，需确认 |

把 `memory_store` 定为 `medium` 是有意的：一条被污染的条目会活过创建它的那次对话。

## 按 key 寻址

记忆以 `key` 寻址（简短、稳定，例如 `coding_style`）。重复写入同一个 key 会更新条目而不是新建重复项，这也是 `memory_store` 在多次运行之间保持幂等的原因。
