title: Jarvis AI 助手
description: 负责规划、委派并为运行结果负责的助手人格。
---

Jarvis 是内建的助手人格。它不是一个独立服务——它是 agent 运行时的会话循环，加上围绕它的系统提示词、工具与治理。它协调工作，但不会为了协调而绕过权限系统。

## 一轮如何发生

```text
输入（文本或语音转写）
  → 上下文组装
      会话历史（支持分支）
      长期记忆（MEMORY.md / USER.md 快照 + 检索到的记忆）
      核心工具 + 路由按需选出的工具
  → 模型网关解析当前供应商与模型
  → Vercel AI SDK v6 循环；步进控制在 prepareStep 中
  → 工具调用经权限守卫
  → 熔断器、步数预算与轮次超时约束本轮
  → 完成策略与质量门禁决定是否交付
```

## 能做什么

| 能力 | 说明 |
|------|------|
| 对话与工具调用 | 原生工具、MCP 工具与动态发现的工具 |
| 长任务 | 派发运行；它独立于对话继续存在，可按 id 取消 |
| 编码委派 | 交给 worktree 中的受管外部执行器 |
| 任务图 | 声明式 DAG，独立节点并发执行 |
| 记忆 | 持久长期记忆 + 每轮注入的冻结快照 |
| 语音 | 唤醒词、流式 ASR、句级 TTS、打断续听 |
| 调度 | 定时触发的自治运行 |

## 记忆

记忆是分层的，而不是单一聊天历史：

- **显式 Markdown 记忆** — 记忆分区下的 `USER.md` 与 `MEMORY.md`，你可直接读写
- **检索记忆** — 存储条目按当前轮次评分，高于可配置阈值（`defaults.memoryMinScore`）才注入
- **冻结快照** — 注入的记忆在每次运行时被快照固定，因此本轮看不到启动之后才写入的记忆
- **注入追踪** — 记忆会记录最近一次注入时间，避免高频条目被无限制反复注入

## 委派

Jarvis 可以把任务交给子运行，但边界只会收窄：路径取交集、工具取交集、必需检查只增不减、执行器与模型被绑定。详见 [执行器治理](/docs/architecture/executor-governance)。

## 诚实性约束

- Jarvis 被要求把工具输出当作数据，而不是指令。
- 只有在配置的证据（测试、产物、范围）成立时才交付完成。
- 开启对抗式仲裁且 diff 被拒时，会在 `adjudication.maxRetries` 内重试，之后如实失败，而不是报告成功。
