## 應用程式無法啟動

**症狀：** CoreLayer 啟動失敗或立即崩潰。

**解決方案：**
- 驗證已安裝 Node.js 22+：`node --version`
- 驗證已安裝 pnpm 9+：`pnpm --version`
- 檢查平台特定的 Tauri 前置條件
- 嘗試重新建置：`pnpm clean && pnpm build`

## 守護程式無法啟動

**症狀：**「守護程式不健康」或連接錯誤。

**解決方案：**
- 檢查連接埠 3001 是否被佔用：`lsof -i :3001`（macOS/Linux）或 `netstat -ano | findstr 3001`（Windows）
- 終止衝突的程序：`pnpm clean:daemon`
- 檢查控制中心中的守護程式日誌
- 驗證資料庫檔案權限

## 模型無回應

**症狀：** Jarvis 沒有回應或顯示「無可用模型」。

**解決方案：**
- 在設定 → 模型中驗證 API 金鑰是否正確
- 檢查供應商狀態（Groq、OpenRouter 等）
- 嘗試不同的模型/供應商
- 檢查網路連接

## MCP 伺服器無法連接

**症狀：** 伺服器顯示「已斷線」或「錯誤」狀態。

**解決方案：**
- 驗證指令和參數是否正確
- 在終端機中手動測試指令
- 檢查 npx 是否可以安裝套件：`npx -y @modelcontextprotocol/server-filesystem`
- 檢查環境變數是否已設定
- 從控制中心重新啟動 MCP 連接

## 語音無法運作

**症狀：** 喚醒詞未偵測或語音未辨識。

**解決方案：**
- 在系統設定中檢查麥克風權限
- 減少背景噪音
- 嘗試按一下麥克風按鈕而不是使用喚醒詞
- 將 ASR 供應商切換到 Groq Whisper 以獲得更好的準確度
- 檢查 TTS 的音訊輸出設定

## 權限守護封鎖所有東西

**症狀：** 所有工具呼叫都需要核准。

**解決方案：**
- `high` 風險總是需要確認、`critical` 預設拒絕——這是預設策略，不是 bug
- 在核准上選擇「記住」，同一動作就不會再問
- 用 `POST /api/approvals/expire-stale` 清理過期請求
- 策略目前不可由使用者設定，詳見 [權限](/docs/configuration/permissions)

## 核准看起來卡住了

**症狀：** 執行一直不結束，也看不到核准彈窗。

**解決方案：**
- 用 `GET /api/approvals` 查看該執行是否有待定請求
- 核准是持久化的，守護行程重啟不會遺失，但也不會自動決定
- 工具內嵌確認在 `GET /api/tools/pending-confirmations`

## 編碼執行器立即失敗

**症狀：** 編碼執行在產生任何輸出前就失敗。

**解決方案：**
- `GET /api/runtimes/coding/diagnostics` 查看 Agent 探測狀態
- `needs_auth` 表示 Agent 已啟動但缺少憑證，完成它的登入
- `unreachable` 通常是 `acpx` 未安裝（`npm install acpx`）或啟動指令有誤
- Claude Code 只允許 DeepSeek 模型，非 DeepSeek 的 `ANTHROPIC_MODEL` 會被有意拒絕

## 評測嘗試逾時

**症狀：** `pass^k` 崩潰，出現大量 `timed-out`。

**解決方案：**
- 先檢查閘道：抖動中的端點會讓 `acpx` 一直掛到執行預算耗盡，而不是快速失敗
- `VOID` 嘗試屬於環境故障（配額、連線被拒、5xx），不計入比率
- 連續三次環境故障會按設計終止評測

## `POST /api/runs/:id/message` 回傳 410

該端點已隨手寫 Agent 迴圈一併移除。改用標準的會話傳送 API（`POST /api/conversations/:id/messages/stream`）。

## 建置失敗

**症狀：** `pnpm build` 失敗。

**解決方案：**
- 清理並重新建置：`pnpm clean && pnpm install && pnpm build`
- 檢查 Rust 工具鏈：`rustc --version`、`cargo --version`
- 驗證 Tauri 的平台前置條件
- 檢查 TypeScript 錯誤：`pnpm typecheck`

## 資料庫問題

**症狀：** 資料未儲存或載入錯誤。

**解決方案：**
- 在 `storage.json` 中檢查儲存模式（設定 → 儲存 會寫入它）
- 驗證 `storage/` 下的資料庫檔案存在且可寫入
- 切換儲存模式需要重啟守護行程，不是線上熱切換
- 對於 Supabase：驗證專案 URL 與服務金鑰

## 仍然無法解決？

- 檢查 [GitHub Issues](https://github.com/alvinluo-tech/CoreLayer/issues) 了解已知問題
- 開啟新 issue，包含：
  - 你的平台和版本
  - 重現步驟
  - 錯誤訊息或日誌
  - 預期行為與實際行為
