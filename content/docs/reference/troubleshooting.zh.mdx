title: 故障排除
description: 常见问题和解决方案。
---

## 应用无法启动

**症状：** CoreLayer 启动失败或立即崩溃。

**解决方案：**
- 验证 Node.js 22+ 已安装：`node --version`
- 验证 pnpm 9+ 已安装：`pnpm --version`
- 检查平台特定的 Tauri 前提条件
- 尝试重新构建：`pnpm clean && pnpm build`

## 守护进程未启动

**症状：** "守护进程不健康"或连接错误。

**解决方案：**
- 检查端口 3001 是否被占用：`lsof -i :3001`（macOS/Linux）或 `netstat -ano | findstr 3001`（Windows）
- 终止冲突进程：`pnpm clean:daemon`
- 在控制中心检查守护进程日志
- 验证数据库文件权限

## 模型无响应

**症状：** Jarvis 不响应或显示"无可用模型"。

**解决方案：**
- 在设置 → 模型中验证 API 密钥是否正确
- 检查提供商状态（Groq、OpenRouter 等）
- 尝试不同的模型/提供商
- 检查网络连接

## MCP 服务器无法连接

**症状：** 服务器显示"已断开"或"错误"状态。

**解决方案：**
- 验证命令和参数是否正确
- 在终端中手动测试命令
- 检查 npx 是否可以安装包：`npx -y @modelcontextprotocol/server-filesystem`
- 检查环境变量是否已设置
- 从控制中心重启 MCP 连接

## 语音不工作

**症状：** 唤醒词未检测到或语音未识别。

**解决方案：**
- 在系统设置中检查麦克风权限
- 减少背景噪音
- 尝试点击麦克风按钮而不是使用唤醒词
- 切换 ASR 提供商到 Groq Whisper 以获得更好的准确度
- 检查 TTS 的音频输出设置

## 权限守卫阻止一切

**症状：** 所有工具调用都需要审批。

**解决方案：**
- `high` 风险总是需要确认、`critical` 默认拒绝——这是默认策略，不是 bug
- 在审批上选择“记住”，同一动作就不会再问
- 用 `POST /api/approvals/expire-stale` 清理过期请求
- 策略目前不可由用户配置，详见 [权限](/docs/configuration/permissions)

## 审批看起来卡住了

**症状：** 运行一直不结束，也看不到审批弹窗。

**解决方案：**
- 用 `GET /api/approvals` 查看该运行是否有待定请求
- 审批是持久化的，守护进程重启不会丢失，但也不会自动决定
- 工具内联确认在 `GET /api/tools/pending-confirmations`

## 编码执行器立即失败

**症状：** 编码运行在产生任何输出前就失败。

**解决方案：**
- `GET /api/runtimes/coding/diagnostics` 查看 Agent 探测状态
- `needs_auth` 表示 Agent 已启动但缺少凭据，完成它的登录
- `unreachable` 通常是 `acpx` 未安装（`npm install acpx`）或启动命令有误
- Claude Code 只允许 DeepSeek 模型，非 DeepSeek 的 `ANTHROPIC_MODEL` 会被有意拒绝

## 评测尝试超时

**症状：** `pass^k` 崩溃，出现大量 `timed-out`。

**解决方案：**
- 先检查网关：抖动中的端点会让 `acpx` 一直挂到运行预算耗尽，而不是快速失败
- `VOID` 尝试属于环境故障（配额、连接被拒、5xx），不计入比率
- 连续三次环境故障会按设计终止评测

## `POST /api/runs/:id/message` 返回 410

该端点已随手写 Agent 循环一并移除。改用标准的会话发送 API（`POST /api/conversations/:id/messages/stream`）。

## 构建失败

**症状：** `pnpm build` 失败。

**解决方案：**
- 清理并重新构建：`pnpm clean && pnpm install && pnpm build`
- 检查 Rust 工具链：`rustc --version`、`cargo --version`
- 验证 Tauri 的平台前提条件
- 检查 TypeScript 错误：`pnpm typecheck`

## 数据库问题

**症状：** 数据未保存或加载错误。

**解决方案：**
- 在 `storage.json` 中检查存储模式（设置 → 存储 会写入它）
- 验证 `storage/` 下的数据库文件存在且可写
- 切换存储模式需要重启守护进程，不是在线热切换
- 对于 Supabase：验证项目 URL 与服务密钥

## 仍然卡住？

- 查看 [GitHub Issues](https://github.com/alvinluo-tech/CoreLayer/issues) 了解已知问题
- 提交新 issue，包含：
  - 你的平台和版本
  - 重现步骤
  - 错误消息或日志
  - 预期与实际行为
