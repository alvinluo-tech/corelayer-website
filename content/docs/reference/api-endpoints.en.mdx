---
title: API Endpoints Reference
description: The daemon HTTP API, grouped by resource.
---

The daemon exposes a loopback HTTP API (`127.0.0.1:3001` by default, `DAEMON_HOST` / `DAEMON_PORT` to override). The Tauri UI reaches it through the shell proxy; tools and scripts can call it directly from the same machine.

Responses are JSON. Collections are wrapped as `{ "data": [...] }` or `{ "entries": [...], "total": n, "count": n }` depending on the route.

## Health and runtime

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/health`, `/health` | `{ status, timestamp, storageMode, aiProvider, aiModel }` |
| GET | `/api/runtime/status` | pid, uptime, memory, storage mode, paths, per-runtime health |
| GET | `/api/runtime/components` | Registered runtime components and status |
| POST | `/api/runtime/shutdown` | Stop the daemon (loopback peers only) |
| GET | `/api/runtime/queue` · `/status` · `/resources` | Queue depth, slot status, resource usage |
| GET | `/api/runtimes/coding/diagnostics` | Coding executor diagnostics |
| POST | `/api/runtimes/coding/:id/dry-run` | Dry-run an executor |

## Approvals

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/approvals` | Pending and recent |
| GET | `/api/approvals/:id` | One request |
| POST | `/api/approvals/:id/approve` | Approve and resume |
| POST | `/api/approvals/:id/deny` | Deny and fail the run |
| POST | `/api/approvals/:id/remember` | Approve and store a permission memory |
| POST | `/api/approvals/batch/approve` · `/batch/deny` | Batch decisions |
| POST | `/api/approvals/expire-stale` | Close unanswered requests |

There is no `/api/permissions/*` group. Approvals and audit are separate resources.

## Authentication

No token is required: the API is bound to loopback and is not exposed to the network. `/api/runtime/shutdown` additionally checks that the peer address is loopback.
